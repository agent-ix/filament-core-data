# EARS conformance review

## Summary

The 12 requirement documents of issue #36 (FR-091 through FR-099, NFR-031
through NFR-033; US-015 read for context only) carry roughly 130 SHALL-bearing
statements. `quire validate --summary` (quoin 0.13.0 engine) reports
`12/12 docs grammar-clean, 0 grammar finding(s)` and no `[ears:*]` or
`[quality:*]` warning for any file in scope, so every finding below comes from
reading each Behavior bullet and Constraint cell against the EARS patterns.
Every statement names a subject and no statement uses an `On`/`Upon`/`After`/
`During` trigger. The dominant defect is non-singularity: about 30 Behavior
bullets join two or more obligations with `and SHALL` or a semicolon, which
the engine does not flag because each bullet is parsed as one enumerated
statement. The second defect class is unwanted-behaviour obligations stated
as `Where …`, `the refusal above applies`, or `SHALL fail the test` instead
of `If …, then the frontend SHALL …`. Neither class changes what gets built;
both degrade the one-statement-one-AC mapping the Test Matrix depends on.
Verdict: conformant in subject and trigger, non-conformant in singularity;
no high finding.

Line numbers below are the line in the named file.

## Proposed rewrites

Representative rewrites; every line listed in a finding follows the same
pattern. No requirement file is edited by this review.

- FR-091 L44: `The frontend SHALL load the bundle's documents with quire_rs::corpus::load_repo over the bundle root.` / `The frontend SHALL treat the document set load_repo returns as the bundle.`
- FR-091 L49: `If a module's semantic_core names a version the pinned engine has no vendored bundle for, then the frontend SHALL refuse with MODULE_REFUSED carrying the engine's semantic.unsupported-semantic-core code.` / `The frontend SHALL NOT lower any artifact of a bundle whose module was refused.`
- FR-092 L48: `If a target is ix://<other>/type/<Name> where <other> is neither the bundle package nor an imports key, then the resolver SHALL return Unresolved::Foreign naming <other>.`
- FR-093 L46: `The frontend SHALL set displayName to … .` / `If neither the title nor the name yields a semantic-core Identifier, then the frontend SHALL raise agent-ix.extraction-frontend.UNNAMEABLE_ARTIFACT at the frontmatter.`
- FR-093 L57: `If FieldDecl.identity is true, then the frontend SHALL carry it as the extension ix://agent-ix/semantic-core/ext/identity-field (version 1.0.0, required: false, payload {}).`
- FR-094 L50: `If a verb is declared by no loaded module's edge_types, then the frontend SHALL raise UNKNOWN_EDGE_VERB at the edge's locus, blocking.` / `The frontend SHALL emit no category for an edge whose verb no registry declares.`
- FR-094 L62: `If OperationDecl.returns resolves to an Unresolved state, then the frontend SHALL raise the FR-092 diagnostic for that state at the Returns: line.`
- FR-094-CON-1: `The frontend SHALL emit a ## Properties row whose type resolves to a bundle object as a field, never as a relationship.` (Move the #34 fixture history to Rationale.)
- FR-096 L62: `If any diagnostic is blocking, then the frontend SHALL write no IR document.` / `If any diagnostic is blocking, then the frontend SHALL leave a pre-existing output path byte-unchanged.` / `If any diagnostic is blocking, then the frontend SHALL exit non-zero.` / `If no diagnostic is blocking, then the frontend SHALL write the document and exit zero.`
- FR-096 L63: `The frontend SHALL emit no message containing an absolute path, a timestamp, a hostname, or a duration.` / `If a token exceeds 100 characters, then the frontend SHALL truncate it with … so that the message is at most 120 characters.`
- FR-097 L55: move to Verification: `TC-1273 computes the SHA-256 of each embedded schema and compares it to the tree copy.` Behavior keeps: `The frontend SHALL embed schema/semantic/v1/semantic-ir.schema.json and common.schema.json byte for byte.`
- FR-097 L65: `The frontend SHALL compute sha256:<64 lowercase hex> over exactly the bytes it writes.` / `The frontend SHALL record the digest in <out>.fingerprint with algorithm rfc8785-v1 and the digest member prefixed sha256:.` / `The frontend SHALL NOT define a second canonicalization or digest scheme.`
- FR-098 L55: `The frontend SHALL name every copied fixture document in a PROVENANCE.json beside it, carrying source repository, revision, and path.` / `If a fixture document has no provenance row, then the provenance test SHALL fail naming the document.`
- FR-098 L60: `The frontend SHALL write goldens only through extraction-frontend lift --write-goldens.` / `The frontend SHALL record each written golden's fingerprint in the fixture's expected/.`
- FR-098-CON-2: `A fixture change SHALL be accompanied in the same commit by a new provenance row and a regenerated golden.` (Validation: change-set inspection.)
- FR-099 L48: `If --diagnostics is given, then the command SHALL write every FR-096 diagnostic to that file in canonical form.` / `If --diagnostics is absent, then the command SHALL print each diagnostic to standard error, one per line, in FR-096 order.`
- FR-099 L51: `The command SHALL exit 0 when no diagnostic is blocking, 1 when any diagnostic is blocking, and 2 on a refusal of FR-091 or FR-097.` / `If the exit code is 1 or 2, then the command SHALL write no document.`
- NFR-031 AC-6: replace `within a bounded memory and time budget` with the values the limit-probe test enforces, for example `within 512 MiB resident and 30 s wall time`, or `within the memoryBudgetBytes and timeBudgetMillis that limits.json declares`.
- NFR-031 Statement: `The extraction frontend SHALL produce byte-identical IR and diagnostic output for identical bundle, module, and limit inputs on the pinned toolchain.` / `If an input exceeds a declared limit, then the extraction frontend SHALL terminate with a blocking, source-located diagnostic naming the limit.`
