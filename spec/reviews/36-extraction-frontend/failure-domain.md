# Failure-domain review

## Summary

The issue #36 set is unusually explicit about its trust boundary — every
declaration comes from `quire_rs::semantic::extract_semantic`, every ambient
input is named and banned, and every defect has a registry code — so the
gaps are not in what the frontend refuses but in what it assumes about the
engine it consumes and about the identities it mints. Reading the requirements
against the engine as it exists (`src/semantic/{surface,decl,clauses,context,
contract,properties}.rs` at the revision NFR-033 pins) finds three highs: the
lift-time gate is schema-only, so every FR-050 cross-field defect the frontend
can produce (composite cycles, duplicate identities, import references with no
lock) is written and fingerprinted as a good document; the slug lowercases
`displayName` while `DUPLICATE_TYPE_NAME` compares it case-sensitively, so two
case-distinct records mint colliding field, constraint, relationship, and
clause identities; and FR-092's `Ambiguous` and `Enumeration` states are
unreachable because the engine already refuses ambiguity as an error and files
every enumeration under `objects` as well. The mediums are the identity model
(title versus `displayName` versus index name, duplicate and absent `id`),
the stale-reference cascade from a declared non-blocking legacy sibling,
engine diagnostics carrying line 0, import references the independent reader
cannot resolve, and the two-file "atomic" write. Purity is close to sealed;
the residue is a cwd-relative provenance path, the crate-version source, and
limits that bind only after `load_repo` has already read everything.

## Failure Dispositions

| Failure | Required disposition |
|---|---|
| Composite self-edge or composite cycle among minted relationships | Refuse at lift with a frontend code at the closing edge's locus; never write |
| Two records whose slugs coincide | Refuse at the second document; never mint a second node under the first's slug |
| Engine `semantic.ambiguous-type` (error, row dropped) | Carried as `ENGINE_DIAGNOSTIC` and `ARTIFACT_NOT_LOWERED`; the frontend does not re-classify |
| Token equal to one artifact's `id` and another's `title` | One rule, shared with the engine; whichever wins is written down, and the loser is named in `related` |
| Reference to an artifact that was not lowered | Blocking, with `related` pointing at the cause's own diagnostic |
| Object-typed artifact with `fields` `not_applicable` | Lowered as a record with `fields: []`, or refused — never silently absent |
| Engine diagnostic with `line == 0` | No `locus`; sorts first; message carries the document path |
| Duplicate or absent document `id` | Refuse at the offending document before any extraction |
| Import reference in the emitted document | Accompanied by the export list the reader needs, or refused in this ticket |
| Crash between document rename and sidecar write | Reader can detect the mismatch: sidecar written first, document renamed last, and `<out>.fingerprint` recomputed by `inspect` |
| Output path under a bundle or module root | Refuse with `OUTPUT_UNWRITABLE` before loading |
