# Risk and complexity review

## Summary

Issue #27 lifts the issue #4 prototype — a TypeSpec `$onEmit` semantic-IR
emitter, hand-rolled Rust/Serde and TypeScript backends, and a JSON Schema
adapter for `datamodel-code-generator` — out of `spikes/typespec-feasibility/`
into `src/compiler/`, deletes the `file:` emitter package, and keeps the frozen
spike replaying its retained evidence through the promoted code with exactly one
declared byte delta.

The bundle's central bet is that byte-identity with the frozen goldens is a
sufficient oracle. That bet has two independent problems. First, the goldens are
not host-invariant: `spikes/typespec-feasibility/evidence/toolchain.json` is
retained evidence, it is compared byte-for-byte by `--check`, and it records the
host's `node`, `pnpm`, `rustc`, `cargo`, and `python3` versions. The drifting
`Cargo.lock` that NFR-017 was written to fix is one of at least five host
couplings in the same gate, and the repository's only CI workflow is a
`workflow_dispatch` call to the shared Node build-test action that never runs
`spike:typespec:check` at all. Second, byte-identity over an eighteen-type slice
cannot detect the prototype defects that are visible on inspection — naive
substring rewriting in `rustType`, a hardcoded `Core|Assurance|Wire` namespace
regex, `includes("null")` nullability, `snake()` mangling consecutive capitals —
and no requirement in this bundle adds a single case beyond the slice, so the
promotion's stated purpose (give #21/#22/#23 something supported to build on)
is met by code that provably cannot generate for their namespaces.

The largest structural failures are an inventory whose thirteen-record count and
whose "every `src/compiler/` file is a target" rule contradict each other and
the "no empty `source`" rule, and a permitted-path list that prohibits the very
deletion FR-044 requires. The largest volatility is that everything promoted is
frozen at spike IR `schemaVersion` 1.0.0 while IR v1.1 (#34) and semantic-core
(#35) are already merged and #19 will rewrite `src/compiler/` against them.

## Top hazards

1. FND-360 / FND-361 — the retained-evidence gate is locked to one workstation's node, pnpm, rustc, cargo, and python versions, the lockfile seeding removes its own fallback, and no CI job runs the check; three P0 test cases (TC-357, TC-361, TC-368) have no venue and no host that can pass them.
2. FND-363 — byte-identity with an eighteen-type golden is the whole oracle, and the code it certifies has a hardcoded three-namespace regex plus four unanchored substring rewrites that guarantee wrong output for the very packages #21/#22 will generate.
3. FND-362 — FR-040's inventory cannot close: thirteen records over a three-bullet input, a file-to-record rule that demands records for files with no prototype source, and a Behavior rule forbidding an empty `source`.
4. FND-364 — NFR-017's prohibited-path list forbids the `emitter/` deletion FR-044 mandates, and the changed-path gate that actually runs (NFR-006, TC-123/124) has no `src/` entry, so the branch trips a pre-existing gate before any #27 test executes.
5. FND-365 — the promoted compiler is frozen at IR 1.0.0 while IR v1.1 and semantic-core are merged, so #27 hands #19/#21/#22/#23 an artefact that #19 must rewrite, while pinning a six-symbol interface, a CLI contract, and hand-written declarations around it.

## Failure-domain gaps

No failure-domain review has been authored for issue #27; the analysis set for
this bundle currently holds this risk-and-complexity review only. Until one
exists, the gaps most likely to surface there are already visible here and
should be carried into it: purity and host-effect boundaries in the replay gate
(FND-360, FND-368), identity and namespace scoping in the backends (FND-363),
extension and inventory closure in FR-040 (FND-362, FND-376), and the topology
of the two competing changed-path gates (FND-364). The precedent set by SR-037
and SR-041 for issue #35 — a failure-domain review preceding the risk review and
cross-referenced from it — has not been followed for #27, and the missing review
is itself a gap in this ticket's evidence.
