# EARS conformance review

## Summary

The issue #27 bundle carries 68 requirement statements holding 74 `SHALL`
tokens: FR-040 (12), FR-041 (15), FR-042 (13), FR-043 (13), FR-044 (13),
NFR-017 (1) and NFR-018 (1). US-009 is clean — it contains zero `shall`/`SHALL`
tokens, so no normative statement leaked into the story. Quire 0.31.0 (engine
0.46.0) reports `100/100 docs grammar-clean (100%); 0 grammar finding(s): none`
with and without `--summary`, so the deterministic `[ears:*]` and `[quality:*]`
lens flags nothing on any of the eight artifacts; every defect below comes from
reading each statement for pattern fit.

The dominant defect is **subject allocation**: 27 of the 68 statements name a
process (`The promotion`), a document or data file (`The inventory`, `The
inventory limitation`, `This repository`, `The retained Cargo.lock`), or nothing
at all (`SHALL stay`, `SHALL remain`, `SHALL change`, `SHALL be revertible`,
`SHALL NOT be narrowed`) as the party bound by the obligation. None of those can
perform an action, so the obligation is unallocatable — and FR-040 shows the cost
directly, mixing file-subject and test-subject bullets inside one Behavior list.
Secondary defects: five compound Descriptions/Statements carrying two `SHALL`
each, three `Where`/`While` triggers used for per-input conditions that EARS
states as `If … then …`, and a family of obligations with rationale or a factual
assertion welded onto the response.

| FND-400 | high | FR-040 allocates its central obligation three different ways inside one requirement. The Description binds `The promotion SHALL record a written disposition for every component` (line 13) — a process, not a component; six Behavior bullets bind a JSON file (`The inventory SHALL contain one record for each of the thirteen prototype components`, line 31; `The inventory SHALL contain no record whose source is absent or empty`, line 32; `Every record SHALL carry a disposition drawn from the closed set …`, line 33; lines 34-36; `The inventory SHALL record the Rust and TypeScript backends as qualified against the representative slice only`, line 38); and only two bind an actor (`then the inventory test SHALL reject that record`, line 37; `then the inventory test SHALL fail naming that file`, line 39). A file does not contain, carry, name, set or record — the enforcing party is the inventory test, and one implementer reads these as a hand-written JSON file with no gate while another reads them as assertions. Restate every data-shape bullet as unwanted behavior against the named actor, e.g. `If src/compiler/inventory.json holds a number of records other than thirteen, then the inventory test SHALL fail naming the missing or extra component.` | FR-040 |
| FND-401 | high | NFR-018 Statement (lines 18-20) is one sentence carrying two `SHALL`, a process subject, a copula response, and five distinct prohibitions: `The promotion SHALL publish no package, change no consumer, schema, fixture, or catalog pin, and SHALL be revertible by reverting its own commits, leaving the issue #4 spike as the only generator once more.` `SHALL be revertible` states a property, not a response, and the `catalog pin` prohibition appears in no metric row and no acceptance criterion — the Measurement table gates packages, four path families, corpus files, the export surface, licence and revert rehearsal, but never a catalog pin, so a stated obligation reaches implementation with nothing verifying it. Split into: `The changed-path gate SHALL fail if the promotion change set modifies a consumer, schema, fixture, or catalog pin.`, `The release gate SHALL fail if the promotion change set publishes a package.`, `The revert rehearsal SHALL restore spikes/typespec-feasibility/emitter/ and the origin/main evidence/custom.json command by reverting the promotion commits alone.` — and add a metric row for the catalog pin. | NFR-018 |

Restate as two statements, one per backend, and move `this equivalence is the promotion oracle` to Rationale or to the FR-042 Description. | FR-042 |
