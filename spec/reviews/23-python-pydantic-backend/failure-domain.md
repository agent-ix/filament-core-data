# Failure-domain review

## Summary

Issue #23 qualifies an MIT upstream rather than writing a generator: it pins
`datamodel-code-generator` `0.76.0` above both published advisory floors,
declares one immutable profile per output family with a closed prohibited-option
set, refuses five executable schema keys before anything is spawned, runs the
generator in a subprocess with no network inside a scratch root it owns, reads
the generated source with `ast` instead of importing it, and type-checks and
runtime-validates what comes out. The security envelope is the strongest part of
the record — three independent defences against remote refs, a refusal register
asserted against the installed distribution's own source, an allow-list that
defaults to refuse, and a falsification test behind almost every gate.

The defects are elsewhere, and they cluster in four places. The first is
attribution: FR-078 hangs the whole inspection on mapping a generated annotation
back to a schema pointer and never says how, while the pinned generator neither
carries provenance into its output nor preserves one symbol per schema node.
The second is the input: the record generates from thirteen published documents
that `$ref` each other by relative filename, and the ref guard, the scratch-root
confinement, `--strict-refs`, the one-module-per-document layout, the
`__init__.py` re-export and the import allow-list each assume a different answer
to a question no requirement asks. The third is identity: four digests are
minted, one of them ("toolchain fingerprint") is not what its name says, one has
no declared home, and no rule says which invalidates what — while the corpus
sees one `python-backend` adapter where the qualification has five families. The
fourth is the host: `toolchain.json`, `report.json` and `PROVENANCE.json` commit
the running host's interpreter and formatter versions and then byte-compare them,
so a patch-level image bump turns four gates red with nothing changed. Seven
findings are high.

## Failure Dispositions

| Failure | Required disposition |
|---|---|
| A generated annotation must be traced to a schema node | State the attribution function as a requirement — the generator's own model-to-source mapping, or a preparation-pass index keyed on the `$defs` name the generator derives its class name from — and state what happens when it is many-to-one or one-to-many before any census equality is asserted |
| Two schema pointers collapse into one generated symbol, or one node mints several | Classify per *symbol* against the set of nodes attributed to it, sanction the annotation only when every attributed node is unconstrained, and replace FR-078-AC-3's node-count equality with a rule that survives reuse and suffixed duplicates |
| Generation takes more than one schema document | Name the input mode explicitly — bundled to one document, or copied as a set into the scratch root — and restate the ref guard, the confinement metric, the module layout and the import allow-list against that one answer; permit intra-package relative imports by name |
| Two documents define the same `$def` | Decide one symbol per identity, state the module that owns it, and make a name collision in `__init__.py` a failure rather than a shadowing; `__all__` completeness is not a collision check |
| The corpus is asked to judge the Python surface | Give the register one slot per family, or state which single family is `python-backend` and why the other four are out of scope; and either amend the corpus paths under a declared change, or state plainly that the corpus branch is unreachable in this ticket and gate it on issue #52 |
| A corpus row runs and disagrees with the oracle | Report it as `failed` in the corpus's own four-number vocabulary; an unmet row is one no adapter was asked, a failed row is one that answered wrongly, and no declaration may move a row from the second class to the first |
| A profile, a schema, or the toolchain changes | Publish the invalidation lattice: which digest each artefact cites, which digest each change moves, and what a moved digest invalidates. Rename the "toolchain fingerprint" to what it actually digests, and give the toolchain its own fingerprint over versions alone |
| A content fingerprint is required to change on any generated byte | Give it a declared home, exclude it from its own input, and state that rule; a fingerprint whose storage is unstated proves nothing on a fresh checkout |
| The host's interpreter or formatter moves by a patch release | Pin the interpreter explicitly and declare an exact version for every recorded tool; then decide, for each committed record, whether a host fact belongs in it at all — corpus-derived bytes are committed and gated, run-derived host facts go to the run report |
| A construct is lost by some families and retained by others | Make the register row per construct *and* per family, with its own severity, closability and disposition; a family removed from a row while the construct stays lost there is narrowing, and is forbidden on the same terms as narrowing the refusal register |
| A schema is mutually recursive, or recursive across two documents | Probe it: self-reference, mutual recursion, and a cycle spanning two modules are three distinct cases. Name the resolution mechanism for every demonstrated family, permit it at module level, and declare a recursion-depth limit beside the wall clock and the input size |
| Generation is killed mid-write | Remove the caller-named output as well as the scratch root, or leave neither and fail naming what remains; state the scratch root's parent, its uniqueness rule, and its removal obligation on every failure path |
| The runner builds the subprocess environment | Scrub `TMPDIR`, `TMP` and `HOME` alongside the proxies and `PYTHONPATH`, and declare the timeout's value, its unit, and that it is not an input to any byte-comparison gate |
| A profile targets a Python or Pydantic version | Reconcile the Description with FR-073-AC-1 — one profile per family, or one per combination with a keyed id — and assert `targetPythonVersion` against the interpreter that imports, type-checks and runs the examples, not only against what the generator accepts |
| An error path or test id is allocated | Take the next free id; `ERR-070`..`ERR-081` are the compiler's, and this route's block starts at `ERR-100` |
| A row block is added to the Test Matrix | Update the Execution Summary prose in the same edit as the table; two stated totals is one stated total too many |
| A gate this change adds has to run in CI | Add `.github/workflows/**` to NFR-026's permitted list explicitly, and give the type-checker configuration a permitted path |
