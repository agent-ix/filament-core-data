# Failure-domain review

## Summary

Issue #22 builds a generation backend: a target-keyed seam over the published
`compiler-request`/`output-manifest` contracts, a type projection for the eight
IR kinds, a self-contained runtime validator, identity and fingerprint metadata,
the backend's own admissibility reader and canonical form, and the
`typescript-backend` conformance adapter that answers the issue #20 oracle. The
premise is right and better guarded than the prototype it replaces: every value
is taken from an IR member rather than from a rendered name (FR-064-CON-2), the
reader and the canonicalizer are second implementations forbidden from importing
the compiler's (FR-068-CON-1, FR-069-CON-1), `unsupportedFeaturePolicy` is
honoured as `fail` rather than as `unknown`, and the adapter is forbidden from
deriving its answer from the oracle (FR-070-CON-1) with a falsification
criterion behind it (FR-070-AC-6).

The gaps are where the IR's value domain meets JavaScript's, and where the
bundle asserts an agreement it has not costed. Six are structural. The
admissibility depth bound is never named, and the two numbers already in the
tree differ by a factor of two — `DEFAULT_LIMITS.maxDepth` is 128 and the
oracle's `DEPTH_LIMIT` is 256 — against a threshold that permits zero
divergences. The adapter must return `normalized` for all 111 cases including
the invalid ones, and the canonical form sorts thirteen containers by
`identity`, which is not a total order on precisely the documents where
`DUPLICATE_IDENTITY` fires. Two of the four committed bases carry an
`occurrence`, a document-level `extension`, and a field `unit`, and nothing in
FR-064 through FR-067 renders any of the three while FR-068's representability
list names none of them — so the richest inputs generate a package that drops
contract data silently, which is the one thing `unsupportedFeaturePolicy: fail`
exists to prevent. FR-070 asks the generated validators to accept and reject
"the payloads a case supplies", and `corpus-case.schema.json` has no payload
member at all. `bytes` is rendered as `string` with no declared encoding while
`maxLength` counts its octets. And a validator promised never to throw is
specified to read arbitrary attacker-supplied objects with no statement about
throwing getters, `__proto__`, or null-prototype inputs. Six findings are high.

Acted on in the review pass: this analysis produced the largest number of
substantive changes. The depth bound, the canonicalization tie-break, the
unrendered contract data, the `bytes` representation, the code vocabulary and the
validator's hostile-input rules all became stated obligations, and two findings
reached a contract defect no requirement here could fix and were filed as
`agent-ix/filament-core-data#62` and, with the sibling's existing report, cited
to #58. The per-finding record is the disposition table at the end of this
document.

## Failure Dispositions

| Failure | Required disposition |
|---|---|
| A resolution walk is bounded | The bound is a stated contract number, identical in the backend, the adapter, and the corpus; the adapter runs at it explicitly rather than inheriting a CLI default, and a mismatch with the oracle's bound is a spec defect fixed before the run rather than a divergence recorded after it |
| A container is sorted by `identity` | The comparator is total: identity, then the canonical form of the whole member, both code-point; canonicalization is exercised on a duplicate-identity document, because that is the document the sort has to survive |
| The IR carries a node the target cannot render | It is named in `representability` and generation fails, whatever the node is — an occurrence, a document extension, a field `unit`, an operation, a clause; a node that is neither rendered nor declared lost is the degradation `unsupportedFeaturePolicy: fail` forbids |
| A criterion consumes evidence that does not exist | The criterion is withdrawn or the evidence is authored under this ticket and named; a payload corpus for generated types is a deliverable, not a projection of a contract-document fixture |
| A negative fixture carries a code outside the backend's register | State the mapping once — collapse to the structural code, or refuse the fixture as out of scope — and make the register bijection and the fixture obligation consistent; do not leave two requirements each right and jointly unsatisfiable |
| A scalar is rendered as `string` | Its lexical form is declared: the encoding for `bytes`, the accepted profile for `date`, `datetime` and `duration`, and the brand that stops one being passed where another is meant; a length or a bound is measured in units the declared form actually has |
| A generated validator reads an untrusted value | Every member read is guarded, the result object is built with a null prototype or `__proto__` is refused by name, and the fuzz catalogue is required to contain throwing getters, null-prototype inputs, proxies, and `__proto__`/`constructor` keys — a no-throw promise with no named mechanism is an aspiration |
| A `displayName` changes while an `identity` does not | The classifier calls it `breaking` for the TypeScript target and says why, or identifiers are minted from `identity`; an unmodelled `unknown` reports the right verdict for the wrong reason and the wrong verdict for a doc-comment |
| Two identities mint one identifier | The failure is a representability loss in the backend's own namespace, decided before rendering begins, so the no-file guarantee holds without depending on where in the pipeline the collision happens to be noticed |
| A policy member is required on a kind it does not apply to | The rendering and the validation behaviour are stated per kind, including "inert" where it is inert, and the committed bases' own combinations are the cases the statement is checked against |
| An open type admits unknown members | The index signature's value type excludes `undefined`, or the four-form guarantee is restated as runtime-only for open types; a compile-time proof that holds only for closed types is not the proof the requirement claims |
| A number crosses the contract/JavaScript boundary | `integer`, `NaN`, `±Infinity`, `-0`, and values past `Number.MAX_SAFE_INTEGER` each have a stated accept-or-reject rule, and the canonicalizer's refusal path returns rather than throws wherever a validator can reach it |
| A generation result is reported | The states `generateTarget` may return are enumerated, each with its file-count and diagnostic-count obligation; a state the schema admits and the bundle never produces is declared unreachable rather than left open |
| A default is substituted | It is validated on the same path as a supplied value, or admissibility refuses a default that does not conform to its field; a value certified `ok` that the generated type contradicts is worse than no default |
| A bundle surface is measured | The bundler, its configuration, and the symbol-extraction method are named and pinned; whole-package `as const` data is split per type or excluded from the claim, so the measurement discriminates rather than reporting whatever the bundler happened to keep |
