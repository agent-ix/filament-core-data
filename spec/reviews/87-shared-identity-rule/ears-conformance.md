# EARS conformance review

## Summary

The CR-087-1 commit (86320f0) changes 21 SHALL-bearing statements across
FR-093 (L60, L69, L72, L73, L83, L85), FR-094 (L63, L71, L72, L78), FR-095
(L88 with nine pattern sub-bullets, L98, L99, L102, L103, CON-4 L119), FR-096
(L63, L64), FR-098 (L162, L163) and FR-099 (L93); adds two citation bullets
with no `SHALL` (FR-034 L55, FR-053 L60); rewrites twelve AC rows; and adds
the 56-line normative section `docs/semantic-data-system/contracts-v1.md`
L117..L172, which is written in the indicative (`the frontend raises`,
`slug(value) replaces`) and carries no `SHALL` at all. `quire validate
--scope . "spec/**/*.md" --summary` (quoin 0.13.0 engine) reports 39 grammar
findings repository-wide, none in a file this change touches, so every finding
below comes from reading each changed sentence against the EARS patterns.
Every changed statement names `the frontend` (or a Make target) as subject and
none uses an `On`/`Upon`/`After`/`During` trigger; the unwanted-behaviour
statements (FR-093 L60, L85; FR-095 L100, L102) are in the `If …, then the
frontend SHALL …` form. Three defects matter: the rule's own definition of
`slug` over an `Identifier` is stated two incompatible ways (contract L146..L151
against FR-095 L89), which changes which `type/` identity a name such as
`Config_Version` mints; the "stated once" rule is in fact restated in five
requirement files in three wordings, with FR-053-AC-10 giving a different
response for the collision case than the contract; and FR-095-CON-4 and FR-099
L93 carry a temporal qualifier that makes their obligation vacuous after the
branch merges. Verdict: CONDITIONAL — one high, four medium, five low.

Line numbers below are the line in the named file on branch
`spec/87-shared-identity-rule` at 86320f0.

## Proposed rewrites

Representative rewrites; no requirement file is edited by this review.

- contracts-v1.md L146..L151: `slug(value) replaces every run of characters outside [A-Za-z0-9] with one -, trims leading and trailing -, and preserves case (Config Version → Config-Version, created_at → created-at, versionNumber → versionNumber). Every part of every slot, the type name included, is slugged.` (Delete `For a name that is already an Identifier, the slug is the name verbatim.`) — or, if the owner intends the verbatim `type/` name, `type/<Name> carries the declaration name verbatim; every other part is slugged, so a name carrying _ mints type/Config_Version and field/Config-Version-<field>.`
- FR-095 L88: `The frontend SHALL mint every node identity by the rule of docs/semantic-data-system/contracts-v1.md §Identity minting, rooted at ix://<org>/<name>/.` / `The frontend SHALL mint no identity by any other rule.` (The slot list becomes a Note that cites the contract table rather than restating it.)
- FR-095 L89: `type: ix://<org>/<name>/type/<slug(displayName)>, or type/<KernelScalar> for a scalar definition.`
- FR-095 L102: `If two declarations of one lift mint the same identity, then the frontend SHALL raise agent-ix.extraction-frontend.DUPLICATE_IDENTITY, blocking, at the declaration later in the order of bundle-root-relative path, then line, then column, naming both identities and carrying the earlier locus in related.` / `If two declarations of one lift mint the same identity, then the frontend SHALL NOT emit either node under that identity.`
- FR-095 L103: `The frontend SHALL mint distinct identity sets for two records whose displayName values differ only by case (Status, status).` (Move the sentence about FR-093's DUPLICATE_TYPE_NAME to FR-093 L60, where it already is.)
- FR-095-CON-4: `The frontend SHALL mint, for every row of test/fixtures/compiler/shared/identity-cases.json, the identity src/compiler/frontend/typespec/identity.mjs mints for that row.` (Validation: Test, TC-1352 and TC-1353.) Record `src/compiler/**, packages/**, conformance/**, schema/** unchanged at merge` in spec/log.md CR-087-1 as a change-set inspection.
- FR-093 L60: `If two documents in one bundle lower to the same displayName, then the frontend SHALL raise agent-ix.extraction-frontend.DUPLICATE_TYPE_NAME at the second document in path order, naming both.` (Note under the bullet: `displayName` is compared verbatim; `Status` and `status` are two names; two names minting one identity are FR-095's `DUPLICATE_IDENTITY`.)
- FR-093 L69: `If a FieldDecl carries one or more constraints, then the frontend SHALL mint one typeDefinition of kind: alias at the alias identity of contracts-v1.md §Identity minting with displayName <DisplayName><Field>, target …, roles: [], unknownPolicy: reject, extensions: [], origin.source the row's locus, and the row's constraints as its constraints[].` / `If a FieldDecl carries one or more constraints, then the frontend SHALL set the field's typeRef to that alias identity.`
- FR-093 L72: `The frontend SHALL lower each Constraint to one IR constraint under FR-029 with appliesTo the alias identity, identity constraint/<Name>-<field>-<keyword>, diagnosticCode as contracts-v1.md §Identity minting derives it, and the row's origin.` (Operand shapes stay as the second bullet they already are in spirit: `pattern carries {regex, dialect} …`.)
- FR-096 L64: delete the appended `DUPLICATE_IDENTITY (…) is error, blocking, raised at …` sentence; `every other code is error, blocking` already covers it and FR-095 L102 owns the locus rule.
- FR-098 L162: `The frontend SHALL produce, for the records-and-scalars case, a parity projection whose normalized form is byte-identical to the normalized projection of the TypeSpec frontend's output.` (AC-7 keeps the comparison procedure.)
- FR-099 L93: `extraction-frontend-evidence SHALL run … -- --ignored, skipping by name only the tests #[ignore]d as blocked on an open issue (TC-1292), so the Static rows they bind have a named producer.`
- FR-053-AC-10: `Two declarations minting one identity raise DUPLICATE_IDENTITY at the later locus by the declared source order with the earlier locus related; a name whose slug is empty raises UNSLUGGABLE_NAME.`
