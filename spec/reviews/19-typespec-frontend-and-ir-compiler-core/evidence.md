# Evidence-method review

## Summary

The issue #19 slice carries 146 advisor-visible obligations — 120 acceptance
criteria across FR-045..FR-052 and NFR-019..NFR-021, plus the 26 NFR metric
rows — and 169 matrix rows at TC-398..566. `quoin advise --json` (2026-09-04)
placed every one of them: zero inconclusive, 17 mismatches, 31 uncatalogued.
The advisor does **not** model the 29 `Constraints` rows in scope; every
`Validation` cell on those rows was judged here, and that judgement is labelled
as such.

Most of the mismatch set is the known lexical pattern SR-021 recorded as FND-034
and SR-031 repeated: `property_shapes=example` / `universal` recommends a Test
method for an obligation authored `Analysis`. In this slice that pattern is
almost always **correct as authored**. Fourteen of the sixteen AC mismatches
(FR-045-AC-6, FR-046-AC-15/16, FR-049-AC-2, FR-050-AC-4, FR-052-AC-13,
NFR-019-AC-3/8/9, NFR-021-AC-1..5) are `Analysis` cells with `Static` matrix
rows — the `Analysis` class and the `Static` evidence kind that
`architecture-conformance` produces, correctly paired. Unlike the
issue #34 slice reviewed in SR-031 (FND-076), the cell and the row here name
the same discharge, and no finding is raised for them. NFR-021-AC-8 is the
catalog's genuine `inspection` / `no-executable-oracle` case, correctly authored
`Inspection` with a `Manual` row.

The residue is where the work is, and it concentrates exactly where the brief
pointed. **NFR-019 and NFR-020 rest their determinism and safety claims on an
instrumented run, an injected reader, an instrumented writer, and an
instrumented loader, and not one of the four names an observation point.** Three
of those claims cannot be observed at all as the requirements are written:
`@typespec/compiler` performs its own file-system access and its own module
loading, and no requirement in the slice makes the frontend hand it a
`CompilerHost`; and every determinism criterion compares two runs inside one
process on one host in one working directory, which is the one comparison that
cannot fail for the reason NFR-019 exists. Those are FND-560, FND-561, and
FND-562.

Below that: six obligations write an *evidence kind* (`Property`, `Fuzz`) into
the `Verification` cell where the catalog expects a method class, which is what
makes them uncatalogued; four `Static` rows carry claims whose subject is a
runtime; one snapshot baseline is regenerable by the code under test; and two
property-shaped criteria sit on `Unit` rows beside identically shaped siblings
typed `Property`.

Nothing in `conformance/` was read or changed, and no spec artefact was edited
by this review.
