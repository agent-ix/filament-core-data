# Failure-domain review

## Summary

FR-045..FR-052 specify a compiler with an unusually complete negative surface:
thirty-three error rows, ten edge cases, a closed diagnostic registry, declared
limits, and an explicit purity and non-disruption envelope. The defects are not
in the individual failure paths, which are well drawn, but in four seams where
two already-frozen artefacts have to meet.

The first seam is the diagnostic. The compiler mints `agent-ix.compiler.*`
codes at source loci, while the reader it must agree with mints
`agent-ix.semantic-ir.*` codes at JSON instance paths, and five spellings exist
in both namespaces for the same defect. The `diagnostic` definition of
`common.schema.json` has nowhere to put an instance path and its `sourceLocus`
cannot express a position inside an imported package, so a whole class of
author-facing failures arrives with no navigable position.

The second is the lock. `package-lock.schema.json` carries no export list and
no kinds, yet FR-050 resolves relationship targets and alias kinds against
`lockExports`, and `schema/**` is prohibited by NFR-021.

The third is resolution. No requirement says which of several satisfying
candidate versions is chosen, so the resolved version — and through it the
fingerprint and every IR byte — is decided by the enumeration order NFR-019
exists to exclude.

The fourth is the digest. `lockDigest` is required on every document and has no
stated provenance when no lock is supplied, and `source.digest` and
`contentDigest` name the same bytes under two requirements without a statement
that they are equal.

Six findings are high. US-010 names the risk they share: a value with no
authority in the input gets invented, and then a golden freezes it.

## Failure Dispositions

| Failure | Required disposition |
|---|---|
| A defect detectable both at the decorator and in the emitted document | One code, in one namespace, raised at the earliest stage that can see it; a second stage re-detecting it is a duplicate, never a second spelling |
| A defect whose only position is a JSON instance pointer | Carry the pointer in a declared field, not in a truncated message; never emit it with no position and let it sort to the end |
| A defect positioned inside an imported package | Locate it by that package's own root plus a package identity; never relocate it to the root manifest and never emit a `..` path |
| A relationship target or alias whose kind lives in another package | Fail with an explicit unresolved-import diagnostic when the export set is absent; never accept the target unchecked and never report a valid cross-package edge as unresolved because no lock was passed |
| Two candidate versions satisfying one import | Resolve by a written total order, or fail; never let enumeration order decide |
| A required digest with no input to compute it from | Fail the compile; never emit a placeholder, a self-digest, or a digest of an absent lock |
| A projection that rewrites a document | Recompute or clear every digest the rewrite invalidated; a projected document must never carry an attestation to inputs it no longer represents |
| More defects than `maxDiagnostics` | Sort first, then truncate, so the retained set is a function of the defects and not of the traversal |
| The repository's own decorator library, read from outside the package root | An explicitly named trusted read in a Behavior clause; every other read outside the root and search directories stays `PATH_ESCAPE` |
| A derived identity colliding with another derived or overridden identity, in any slot | Fail at both loci under one code, ordered by path then position; uniqueness is over the whole document, not per node list |
| `presence` and `multiplicity` disagreeing, in either direction | Fail at the field locus; a derived bound for a collection is never invented from `presence` alone |
| Two documents that differ with no classifiable change | Report the envelope difference as a named family with a stated identity, or fail; never emit an empty `changes` array and never invent an identity to fill the schema |
| A family whose consumer or profile input was not supplied | Name it in `requiredGates`; never classify it and never default it to `patch` |
| A blocking diagnostic after an earlier successful compile | Remove or refuse to leave a stale `--out`; a caller must never be able to read the previous run's IR as this run's |
| A cyclic or unboundedly wide input the declared limits do not name | Bind every limit to a measured structure and terminate with the limit diagnostic; enumeration cost is bounded at the search, not at the report |
