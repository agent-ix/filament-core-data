# Failure-domain review

## Summary

Issue #20 builds a yardstick: a declarative corpus (`base` + RFC 6902 patch), an
independent JSON-level oracle, a differential harness that compares every
adapter with the oracle and never with another adapter, a construct register
with four case classes per row, a coverage account, a mutation catalogue, and an
import API. The premise is right and unusually well guarded on the axes it names
— no backend-versus-backend comparison (FR-037-AC-3, TC-299, TC-300), no
blessing from a run (FR-035-AC-7, TC-286), locale and directory invariance
(NFR-015-AC-2), and a defect register that outlives its defects (FR-038-AC-5).

The gaps are at the seams. Three of them are structural. First, the corpus and
the oracle are authored by the same ticket and checked only against each other
(FR-036-AC-1), so nothing in the requirement set can distinguish a correct
oracle from a confidently wrong one; `derivedFrom` checks that a quote *occurs*,
never that it *entails*. Second, the wire shape the harness compares is not the
contract's diagnostic — `common.schema.json#/$defs/diagnostic` has no `pointer`,
requires `owner`, `blocking`, `causes` and `related`, and is
`additionalProperties: false` — and the match rule drops `locus`, `severity`,
`message`, and the whole compatibility `classification`. Third, a case's inputs
are one semantic IR document, but six of the negative cases FR-038 mandates are
about locks, manifests, mappings, and consumer policies that no semantic IR
document contains and no case field carries. Eleven findings are high.

## Failure Dispositions

| Failure | Required disposition |
|---|---|
| The oracle is wrong about a contract rule | Every expectation cites a clause that *entails* it, checked by a reviewer who did not write the oracle; a disagreement with a merged reader is triaged to a side (oracle defect or adapter defect) before it is registered, and an oracle defect fixes the oracle, never the register |
| An adapter emits a contract-conformant diagnostic | `adapter-result.schema.json` reuses `common.schema.json#/$defs/diagnostic` and adds `pointer` as one named extension; the mapping from `owner`/`blocking`/`causes`/`related` to the compared tuple is written down, not implied |
| An adapter matches on codes and pointers but differs on locus, severity, or normalized bytes | Fail; compare `locus` and `severity` for every case class and `normalized` for every class, not only `positive` |
| A `compatibility` case is run against an adapter | Compare `classification` and the named contributing changes; an adapter that cannot receive the before-document reports `unsupported` with an owning issue, never `success` |
| A mandated negative concerns a lock, manifest, mapping, or consumer policy | Give the case an explicit `context` block carrying those documents, or move the case to a separate compiler-request corpus; never leave it inexpressible against a register row that the coverage gate reports as met |
| One seeded edit yields several schema errors | Count intended violations, not diagnostics: pin the validator's error enumeration and declare the expected diagnostic set per negative case, or decide the case at the cross-field layer where one rule yields one diagnostic |
| A self-referential or mutually recursive construct is read | State precedence explicitly — cycle detection before depth bounding — and require graph-visited resolution so that legal recursion is accepted and only unbounded *expansion* trips the depth limit; author the depth boundary case with a generated base exempted from the `ops` budget, and state that exemption |
| A base document changes | Digest the base, the schemas, both registers, the thresholds, the mutation catalogue, the registry, and the divergence register alongside the cases; every case pins its base's digest and asserts that its built input differs from its base |
| A case digest is recomputed | Name the canonical form (`RFC8785-JCS-with-identity-sorted-sets-v1`), state the `corpusDigest` separator and encoding, exclude `corpusDigest` from its own input, and name the sort key; then restate FR-035-AC-6's mutation test as a mutation of *semantic* bytes |
| An adapter answers a case | The result carries the digest of the input it read; the harness fails any result whose input digest is not the one it built |
| A divergence is registered | The entry names the side believed wrong and the contract clause in dispute; the register's size is a declared, non-increasing budget, and a `reviewBy` date may be extended only by a named reviewer with a recorded reason |
| The harness needs a date | Take the instant from one explicit, injectable input; the report records it, and two runs with the same injected instant are byte-identical |
| Two diagnostics tie on pointer, code, and message | Add a final total tiebreak (severity, then locus, then insertion index) so the order is total; state the pointer sort as code-point order over the unescaped pointer, and use the same ordering for `normalized` key sorting |
| A backend cannot support a construct | Record it in the adapter registry with an owning issue and a review date, not in a case's `expected`; a case's expected result never names an implementation |
| The coverage account is compared byte-for-byte | Split it: corpus-derived rows are committed and gated; run-derived adapter counts go to the run report only, and the harness pins the adapter process environment (locale, working directory, declared toolchain version) |
| The mutation score is reported | Define detection as a case whose verdict *changes* under the mutation, catalogue mutations of the oracle's rules as well as of documents, and have the catalogue reviewed by someone other than the corpus author |
| A discovered defect is not expressible as a document | Record it in the defect register with the reason it has no document-level case and the process-level gate that catches it instead; never mark the register row satisfied by a case that cannot fail on the defect |
| A verdict has diagnostics that are neither errors nor declared loss | Declare the state (a `warning`-only result is `success` with warnings, or `partial`) and define "declared-loss diagnostic" by code; state the single rule that decides `support` versus `resultState` when both could carry `unsupported` or `unavailable` |
| The corpus gates have to run in CI | Add the workflow path to NFR-016's permitted list explicitly, and name one canonical reviews directory |
