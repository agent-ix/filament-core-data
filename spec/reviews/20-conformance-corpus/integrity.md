# Integrity review

## Summary

US-008 is elaborated by FR-035..039 and constrained by NFR-015 and NFR-016
under StR-001. Every acceptance criterion and named constraint reaches a case in
TC-280..332, the ERR-051..063 and EC-038..045 rows are mapped, and the FR ids,
case ids, and family names are internally unique. The bundle is not yet
single-interpretation against the merged contract or against issue #20. Six
defects are structural: the corpus judges only IR-document verdicts, so the
cross-language serialization and codegen divergence the ticket exists to catch
has no case; the case format is a JSON Patch over one semantic IR document and
cannot express the lock, manifest, package graph, mapping, or consumer policy
that six of the negative cases FR-038 mandates require; a self-referential alias
is required to produce an alias-cycle code and `DEPTH_LIMIT_EXCEEDED` at once
under a rule that admits exactly one diagnostic; the `reviewBy` expiry check
requires a clock NFR-015 forbids and makes the report time-varying; FR-036's
compatibility table classifies an optional addition unconditionally `additive`
where the merged contract makes it conditional on consumer policy, and never
classifies the profile, mapping, representation, or generated-target surfaces
the contract includes; and the construct register omits `alias`, `sequence`,
`map`, `enum`, `scalar`, and `extension` families while the ticket also asks for
generics, renames, and deprecations that the IR has no construct for. Twelve
medium findings are undefined terms (`pointer`, `canonical bytes`, "gate",
"declared-loss diagnostic", `covers`, `expected.unsupportedBy`), colliding
vocabulary (`unmet row`, `family`, `support` versus `resultState`), an
FR-035/FR-036 dependency cycle, an unenforced SemVer rule, a per-backend
mutation score with a corpus-scoped definition, and a permitted-path list that
excludes both the corpus's own schema directory and any place to wire the gates.
No spec artifact was edited by this review.

## Findings

| ID | Severity | Summary | Refs |
|---|---|---|---|
| FND-230 | high | The corpus judges IR-document verdicts only. An adapter result carries `support`, `resultState`, `diagnostics[]`, and `normalized` for a case whose input is a semantic IR document, so every comparison is about whether an implementation reads the IR the way the contract says. Issue #20's objective is "detecting silent cross-language codegen divergence" and its deliverables name "cross-language serialization/deserialization, unknown-field, and invalid-payload fixtures"; no requirement declares an instance-level fixture, a round-trip obligation, or a generated-type serializer comparison, so a Rust, TypeScript, or Python backend whose emitted types serialize divergently passes every case in the corpus. | issue #20 deliverables, FR-037, FR-038, US-008, TC-297..307 |
| FND-231 | high | The case format cannot express the inputs the mandated cases need. FR-035 builds a case input as `base` plus an RFC 6902 patch over one semantic IR document and forbids any other transformation, yet FR-038 requires negative cases for an import the lock does not resolve, a package-graph cycle, a mapping naming an undeclared identity, a stale `manifestDigest`, and an omitted identity the profile does not declare as loss, and FR-036 decides a `required: true` extension whose `capability` no declared consumer policy admits. Those inputs live in `package-lock`, `package-manifest`, `mapping`, `profile`, and `consumer-policy` documents. FR-036's "optional resolution context: the lock's exported identities and the declared package graph" has no case field that supplies it, so FR-038-AC-2, ERR-051..ERR-053, ERR-055, ERR-056, and TC-309 have no constructible input. | FR-035, FR-036, FR-038, FR-038-AC-2, ERR-051, ERR-053, ERR-055, ERR-056, TC-309 |
| FND-232 | high | A self-referential alias has two mutually exclusive expected results. FR-036 requires "alias cycles as their own diagnostic distinct from an unresolved reference" and ERR-057 requires an alias-cycle code, while FR-036-AC-3 requires that same self-referential alias to return `DEPTH_LIMIT_EXCEEDED`. FR-035-AC-4 admits exactly one diagnostic for a negative case, so the alias-cycle case cannot carry both; nothing states whether cycle detection precedes expansion or which code is authoritative, and FR-038-AC-4 rejects "an alias cycle and a composite relationship cycle" without naming either code. | FR-036, FR-036-AC-3, FR-035-AC-4, FR-038-AC-4, ERR-057, TC-291, TC-292, TC-311 |
| FND-233 | high | The harness cannot both read the clock and be deterministic. FR-037 fails a run when a matching divergence entry's `reviewBy` date has passed, which is a verdict that changes with no change to the corpus, the adapters, or the register. NFR-015's operational context declares "no clock read" over `conformance/**`, the oracle *and the harness*, and NFR-015-AC-2 requires the harness report and the coverage account to be byte-identical across two runs. No requirement names a reference date (run date, a committed `asOf`, or a CI-supplied value), so ERR-061, TC-302, and TC-326 test contradictory obligations. | FR-037, NFR-015, NFR-015-AC-2, ERR-061, EC-044, TC-302, TC-326 |
| FND-234 | high | FR-036's compatibility table contradicts the merged contract and under-covers it. `contracts-v1.md` states optional additions "are additive only when every target and known consumer preserves, ignores, or surfaces them as declared" and that open/closed enum behavior is consumer policy; FR-036 classifies "an optional field addition and a constraint relaxation as `additive`" unconditionally and "an added enum variant as `conditional`" with no consumer input. The contract further classifies across "semantic, profile, mapping, representation, and generated-target surfaces" and makes reserved-Protobuf-name reuse breaking and invalid, while the oracle classifies only a pair of semantic IR documents — so FR-038's claim to cover "every compatibility rule" and FR-038-AC-8 are unmet as stated. | FR-036, FR-038, FR-038-AC-8, FR-025, `contracts-v1.md` §Compatibility, TC-295, TC-317 |
| FND-235 | high | The construct register omits constructs the contract and the ticket name. The contract's closed structural vocabulary is scalar, record, enum, discriminated union, alias/newtype, sequence, map, and semantic reference, and `semantic-ir.schema.json` enumerates all eight `kind` values; FR-038's seventeen families collapse them into one `kind` family while giving `union` and `recursion` families of their own, and declare no `alias`, `sequence`, `map`, `enum`, `scalar`, or `extension` family. Issue #20 additionally requires cases for aliases, maps, generics, enums, extensions, renames, and deprecations; generics, renames, and deprecations have no IR construct at all and no requirement records that the ticket asks for something the contract does not carry. FR-039-AC-4 sizes the mutation catalogue per family, so every omission propagates into the mutation score. | issue #20 deliverables, FR-038, FR-038-AC-1, FR-039-AC-4, `semantic-ir.schema.json` kind enum, TC-308, TC-321 |
| FND-236 | medium | The diagnostic shape the whole corpus compares on is not the contract's. `common.schema.json#/$defs/diagnostic` requires `code`, `severity`, `message`, `owner`, `blocking`, `causes`, and `related`, and locates a diagnostic with a `locus`; it has no `pointer`. FR-035, FR-036, and FR-037 make `pointer` (an RFC 6901 pointer into the input) the primary key of every expectation and every comparison, and never state `owner`, `blocking`, `causes`, or `related`. `adapter-result.schema.json` is authored by this ticket with no stated content, so whether an adapter that emits contract-shaped diagnostics can answer at all is undecided. | FR-035, FR-036, FR-037, `common.schema.json`, TC-289, TC-298 |
| FND-237 | medium | `resultState` is undecidable for a document whose diagnostics are all non-error. FR-036 defines `success` (no diagnostic), `invalid` (at least one `error`), and `lossy` ("every diagnostic is a declared-loss diagnostic"); a document carrying only `info` or `warning` diagnostics falls in none of the three. "Declared-loss diagnostic" is undefined — the contract's loss vocabulary is the preservation ladder (byte-lossless, structure-lossless, semantic-lossless, declared-lossy) on mappings and profiles, not a diagnostic class, and no code marks one. `common.schema.json` also admits `unsupported`, `unavailable`, and `partial`, which no requirement rules in or out for the oracle. | FR-036, `common.schema.json#/$defs/resultState`, `contracts-v1.md` §Mappings, TC-289 |
| FND-238 | medium | `support` and `resultState` overlap with no precedence rule. FR-037 has an adapter result carry `support` of `supported`, `unsupported`, or `unavailable` alongside a `resultState` whose contract enum already contains `unsupported` and `unavailable`. No requirement forbids `support: "supported"` with `resultState: "unavailable"`, states which field the acceptance rules of FR-037-AC-4 and FR-037-AC-8 read, or says what `partial` means for an adapter. | FR-037, FR-037-AC-4, FR-037-AC-8, `common.schema.json`, TC-301, TC-307 |
| FND-239 | medium | FR-035 and FR-036 depend on each other. FR-036 declares FR-035 upstream, while FR-035-CON-1, FR-035-AC-2, and FR-035-AC-4 define corpus admission in terms of oracle diagnostics ("zero oracle diagnostics", "exactly one oracle diagnostic"). Nothing states which is authored first, how a base document is admitted before an oracle exists, or what the corpus gate does while the oracle is incomplete; the traceable dependency graph for issue #20 is therefore cyclic at its root. | FR-035, FR-035-CON-1, FR-035-AC-2, FR-035-AC-4, FR-036, TC-281, TC-283 |
| FND-240 | medium | "Canonical bytes" and "canonical form" are undefined at the two points a digest is compared. FR-035 digests "that case's canonical bytes" and takes `corpusDigest` over "the identity-sorted case digests"; FR-036-AC-6 requires `normalized` to be byte-identical to "the canonical form of the input document". The contract names exactly one canonicalization, `RFC8785-JCS-with-identity-sorted-sets-v1`, and FR-036 restates only "object keys are sorted by code point" — silent on array and set ordering, number form, and string escaping. Two conforming implementations can produce different digests and different `normalized` bytes for the same case. | FR-035, FR-035-AC-6, FR-036, FR-036-AC-6, `contracts-v1.md` §Packages, TC-285, TC-294 |
| FND-241 | medium | Obligations with no acceptance criterion and no case. FR-035's SemVer bump rules (case addition minor, `expected` change major, prose patch) have no AC and no gate, yet `spec/tests.md` asserts "a minor bump fails the versioning gate" and maps it to TC-285, which tests digests. FR-035's "SHALL NOT delete a case that reproduces a discovered defect", FR-037's "SHALL NOT write to any path outside `conformance/`", and FR-037's "SHALL NOT modify a case file, a base document, or the corpus manifest" likewise have no criterion and no TC row. | FR-035, FR-037, spec/tests.md versioning row, TC-285 |
| FND-242 | medium | "Gate" names six distinct obligations with no defined carrier. The bundle invokes a corpus gate, a coverage gate, a threshold gate, a mutation gate, a versioning gate, and a changed-path gate; no requirement says what a gate is, which command runs it, what exit code it produces, or where it is wired. NFR-016's permitted-path list contains no CI workflow path and permits only new `Makefile` targets and one `package.json` script, so an enforced gate either has no home or the change violates NFR-016-AC-1. | FR-035, FR-038, FR-039, NFR-016, NFR-016-AC-1, TC-329 |
| FND-243 | medium | NFR-016's prohibition swallows the corpus's own schemas. The prohibited list names `schema/**` and `fixtures/**` with no repository-root anchor, while FR-035 requires `conformance/schema/corpus-case.schema.json`, `conformance/schema/corpus-manifest.schema.json`, and `conformance/schema/adapter-result.schema.json`. NFR-016-AC-1 and TC-329 measure "files changed under `schema/`", so the changed-path gate fails the branch that satisfies FR-035 under one reading and passes it under the other. `pyproject.toml` is also absent from the permitted list although NFR-016-AC-2 inspects it. | NFR-016, NFR-016-AC-1, NFR-016-AC-2, FR-035, TC-329, TC-330 |
| FND-244 | medium | The mutation-detection score is defined for the corpus and declared per backend. FR-039 defines it as "the fraction of a fixed, committed mutation catalogue that the corpus detects" — a property of the corpus and the oracle, invariant across adapters — yet requires `thresholds.json` to declare "the required mutation-detection score" separately for issues #19, #21, #22, and #23. No requirement defines a per-adapter score, so FR-039-AC-2 and TC-319 assert a value that FR-039-AC-3 measures differently. "The corpus SHALL declare a backend's thresholds before that backend is promoted" also leaves "promoted" undefined here and has no gate that checks the ordering. | FR-039, FR-039-AC-2, FR-039-AC-3, TC-319, TC-320 |
| FND-245 | medium | Colliding and undeclared field vocabulary. "Unmet row" means an unanswered case from an `unavailable` adapter in FR-037 and a register row with zero cases in FR-039, and both appear in one report. "Family" is a case field and a directory in FR-035 and a register family in FR-038, with no rule that a case's family is a register family. `covers` is required on every case by FR-035 and never defined; `expected.unsupportedBy` is read by FR-037-AC-8 and is absent from FR-035's list of what a case file carries, so `corpus-case.schema.json` has no stated slot for it. | FR-035, FR-037, FR-037-AC-8, FR-038, FR-039, TC-280, TC-307 |
| FND-246 | medium | A compatibility case has no defined comparison. FR-035 gives a `compatibility` case a `classification` in `expected`; FR-037 matches an adapter only on `resultState`, the ordered `code`/`pointer` sequence, and — for a `positive` case — `normalized` bytes, and never reads a classification. FR-035 also requires every `positive` case to declare `resultState: "success"` with an empty diagnostic list, which a classification-bearing pair cannot honor, and FR-038 requires an `evolution` case for every register row. Whether an evolution case is necessarily `kind: compatibility`, and what an adapter must return for one, is unstated. | FR-035, FR-037, FR-038, FR-038-AC-1, TC-297, TC-308, TC-317 |
| FND-247 | medium | The 64-node budget is undefined and collides with the cases it must carry. FR-035 caps `ops` at "64 JSON nodes" without saying whether a node is a patch operation, an object key, an array element, or a scalar leaf, and FR-035-CON-1 requires every base to yield zero oracle diagnostics. The boundary row in `spec/tests.md` sets the reference-expansion boundary at depth 256 versus 257, which neither a diagnostic-free base nor a 64-node patch can obviously reach; FR-038's mutual recursion through two records and its package-version transition that adds and removes an export are in the same position. | FR-035, FR-035-CON-1, FR-035-AC-8, FR-036, FR-038, TC-287, TC-291 |
| FND-248 | low | The contract requires "graph depth, reference expansion, collection sizes, input bytes, and diagnostic volume" to have declared finite limits and terminate with source-located diagnostics. FR-036 declares only reference expansion, at 256 with `DEPTH_LIMIT_EXCEEDED`; graph depth, collection sizes, input bytes, and diagnostic volume have no declared limit and no diagnostic code, although the oracle reads untrusted documents and NFR-015 requires a bounded, deterministic verdict. | FR-036, NFR-015, `contracts-v1.md` §Safety and reproducibility, TC-291 |
| FND-249 | low | Traceability housekeeping. NFR-015's frontmatter constrains only FR-035 and FR-036 although its scope, metrics, and NFR-015-AC-2 govern the harness and the coverage account (FR-037, FR-039); NFR-016 constrains only FR-037 although its permitted list governs FR-035 and FR-039 outputs. FR-035's prose names FR-028 and FR-029 upstream but its frontmatter does not; FR-038's prose names FR-021 and its frontmatter does not. TC-296 (a non-object input) is mapped to FR-036-AC-1, which is about corpus cases, while the behavior it tests has no AC; no ERR row covers a case-digest mismatch, a blessed case with no `blessing` block, or an over-budget `ops`. | NFR-015, NFR-016, FR-035, FR-038, TC-296, ERR-051..063 |
