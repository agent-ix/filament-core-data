# SR-216: scope-boundary review of the endpoint type-resolution and direction batch

## Summary

Eight of the nine named public types survive the batch unchanged and no Quire
wire, reference or tracing schema is introduced, but `RelationshipSemantics` does
not survive: FR-128 replaces its `direction` member's type and the batch
acknowledges that break nowhere, and FR-127 takes ownership of the native export
vocabulary FR-116 explicitly declined to enumerate. Eleven findings follow, four
of them high.

## Findings

| ID | Severity | Summary | Refs | Escape Cause |
|----|----------|---------|------|--------------|
| FND-950 | high | FR-128 is a breaking change to the public API and to the wire contract, and the batch does not say so. `RelationshipSemantics.direction` is today a producer-defined string admitting any spelling; FR-128 replaces it with a closed four-value type, so every previously admitted document whose direction spells anything else — and every downstream caller that reads or constructs the member as a `String` — now fails. The only acknowledgment is FR-128-AC-8's "otherwise unchanged", a weasel that a `Compile` criterion cannot fail on, and FR-115, whose Behavior and AC-1 still carry `direction` as one of the emitted semantics members, is left unamended while FR-128's Dependencies assert it "replaces only the direction member's shape".
