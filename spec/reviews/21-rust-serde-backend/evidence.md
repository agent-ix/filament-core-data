# Evidence-method review

## Summary

The issue #21 slice carries 138 advisor-visible obligations — 116 acceptance
criteria across FR-054..FR-062 and NFR-022..NFR-023, plus the 22 NFR metric
rows — and 100 matrix rows at TC-645..744 with ERR-114..131 and EC-69..EC-81.
`quoin advise --json` (2026-09-04) placed 137 of them: one inconclusive
(FR-055-AC-1), 24 mismatches, 40 uncatalogued. US-011 declares no acceptance
criteria — its five `US-011-EX-*` are marked illustrative — so it contributes no
obligation and appears here only in FND-946. The advisor does not model the 41
`Constraints` rows in scope; every `Validation` cell on those rows was judged
here, and that judgement is labelled as such.

Most of the AC mismatch set is the lexical pattern SR-021 recorded as FND-034
and SR-069 repeated as its own residue: `property_shapes=example` or `universal`
recommends a `Test` method for an obligation authored `Analysis` or
`Inspection`. In this slice that reading is usually correct as authored —
FR-054-AC-11/AC-14, FR-055-AC-10, FR-056-AC-2, FR-057-AC-13, FR-058-AC-10,
FR-060-AC-8, FR-061-AC-9 and the eight NFR-023 `Analysis` cells are all paired
with `Analysis`-typed matrix rows, which is the class and the evidence kind
`architecture-conformance` produces, correctly matched. All 22 metric rows draw
the same single recommendation, `performance-benchmarking` on
`characteristics=quantified-threshold`, matched purely on the numeric `0` target;
not one of the 22 is a performance claim, and this is the same false positive
SR-069 recorded as FND-571. It is noted here so the 22 identical recommendations
are not read as a gap.

The residue is where the work is, and it does not fall where the mismatch list
points. **This slice's determinism and non-degradation claims — the two the
issue's own acceptance criteria 4 and 5 rest on — have no oracle that can
report a failure.** NFR-022 asserts an operational context of "an offline
workstation and an offline CI runner, both with the pinned Rust toolchain", and
`.github/workflows/build-test.yml:8` is a Node-only reusable workflow on
`workflow_dispatch` with no OS matrix and no Rust toolchain: no runner in this
repository can execute a single Rust row, and no second platform triple is named
anywhere in the slice. NFR-022-M-3 then restricts its own population to "the
declared platform matrix rows **with measured evidence**", which is a target of
zero over whatever set happened to run — the exact shape issue #42 records, where
a `--check` gate was green only on the host that minted its evidence. That is
FND-935. Alongside it, the degradation scan that carries acceptance criterion 5
is asserted correct by `Inspection` (NFR-022-AC-2) and has no negative control
anywhere in the slice — FND-936 — and FR-062's mutation score of 1.0 is stated
over a catalogue with no declared operator set, no declared target set, and no
declared size, so nobody else can reproduce it — FND-937.

Below those: FR-057-AC-5's 100000 random subject strings are drawn from an
unnamed alphabet, which makes the differential agreement it measures very
largely mutual rejection (FND-938); FR-059's honest divergence path is
prohibited by NFR-023's own permitted-path list while `conformance/thresholds.json`
holds a one-divergence budget for a gap FR-059 says will not produce one
(FND-939); twenty `Verification` cells carry a matrix `Type` where the catalog
expects a method class, three times the six SR-069 raised as FND-563 (FND-940);
the FR-060 golden is minted by the emitter under test with nothing freezing it
(FND-941); the mapping-table agreement checks compare a JSON file to a Markdown
prose table by an unnamed mechanism, and that prose table's own arithmetic does
not add up (FND-942).

Three things in this slice are better than their issue #19 analogues and are
recorded so they are not lost in a redesign. **FR-059-AC-13** — "removing the
adapter command from the registry returns the slot to 111 unmet rows and zero
passes" — is the negative control the "unmet rows must stay reachable" question
asks for, and it is the model the rest of the slice should copy; the corpus does
carry 111 cases (`conformance/corpus.json`), so the number is measured and not
asserted. **NFR-022-AC-4** discharges the offline claim by removing a cached
crate and observing the failure, which is an oracle that can fail, unlike a run
that merely completes with the network denied. **FR-060-AC-2** varies the
working directory, which is precisely the hole SR-069 raised as FND-560 against
NFR-019, and **NFR-023-AC-9/AC-10** fix both ends of the change range from
history and rehearse accretion on a synthetic history, which is the shape PR #54
landed. **FR-057-AC-6** is exhaustive over a named 7-symbol alphabet at lengths
0 to 6 and is the strongest single criterion in the slice.

No spec artefact or source file was edited by this review; this file is the only
one written.
