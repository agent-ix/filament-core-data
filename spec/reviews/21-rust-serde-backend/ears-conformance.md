# EARS review

## Summary

Every SHALL-bearing statement of issue #21 — FR-054 through FR-062 and NFR-022,
NFR-023 — was read one by one for pattern fit; US-011 was read for context only,
as a `As a / I want / So that` story carries no requirement statement. No
statement in scope opens with a non-canonical `On`/`Upon`/`After`/`During`
trigger, no statement uses `support`/`handle`/`manage`/`process`/`provide`/
`enable` as a response verb, and the unwanted-behaviour obligations consistently
use the `If … then the backend SHALL raise <code>` form with a code drawn from
the closed `agent-ix.rust-backend.*` registry FR-058 declares. The scope contains
no `MAY` statement.

Quire 0.31.0 (engine 0.46.0) over the whole tree reports
`147/157 docs grammar-clean (93%); 32 grammar finding(s): ac:vague-response=1
ears:non-singular=24 quality:agentless-passive=7`. One `ears:non-singular` on
FR-031 line 56 is pre-existing and merged; the other **31 findings all fall in
this scope**, and this review's bar is that none of them is an *unclassifiable*
or *missing-subject* statement — there are none of either — not that the count is
zero.

Two facts about the linter matter for reading the table below. First, the linter
treats each **physical line** as one statement, so a sentence wrapped across
lines can produce a spurious `non-singular`. **No such wrap artefact occurs
here**: all 24 in-scope `ears:non-singular` findings land on rows of a
`## Constraints` table, which are single physical lines carrying two to four
genuine `SHALL`s each (FND-913). The error runs the other way — several
multi-obligation Behavior bullets *are* wrapped across lines and the linter
therefore cannot see them at all (FND-915). Second, the single
`ac:vague-response` finding, FR-056 line 123, fires on the noun phrase
`the support matrix declares`; `support` there is a noun, not a response verb,
and the finding is a **false positive** (FND-918).
