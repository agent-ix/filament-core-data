# Failure-domain review

## Summary

FR-054..FR-062 specify a backend whose negative surface is unusually well drawn:
twelve registered codes, eighteen error rows, thirteen edge cases, a closed
mapping table, a refusal policy that forbids every silent degradation the issue
#4 prototype committed, and a proved-validator regime for the one published
pattern RE2 cannot compile. The defects are not in the refusals. They are in the
places where the mapping table's rows are read against the *schema's* actual
key, where a Rust or serde mechanism is named without the attribute that would
make it behave as claimed, and where a construct nobody wrote down is legal in
the IR and legal to the reader and lands in `rustc`.

The first seam is the mapping key. FR-054's table selects on `kind`, but three
of its rows are decided by something else — `payloadType` on a variant, which
the schema does not tie to `kind`; `unknownPolicy`, which the schema requires on
all eight kinds while only the `record` row can carry the flattened member the
rule prescribes; and a `multiplicity` whose `{lower: 0, upper: 0}` means "never
present" and maps to a type that admits a value. FR-054-CON-1 asserts the
mapping is total over the vocabulary. Walked construct by construct, it is not.

The second is serde. `Nullable<T>` is introduced precisely so an absent member
and a present `null` stay distinguishable, and then composed as
`Option<Nullable<T>>` under derived serde, where `Option`'s own `Deserialize`
eats the `null` first and `None` serializes back as `null`. FR-054 names not one
serde attribute on the presence axis — no `default`, no `skip_serializing_if`,
no `deserialize_with` — so the mechanism as written cannot satisfy FR-054-AC-4,
which is also EC-69.

The third is recursion. The boxing rule quantifies over *fields*. A cycle that
closes through an `alias` target or a `union` variant `payloadType` reaches no
field, is not caught by `reader.mjs` (which never resolves `target`, `items`,
`values`, or `payloadType`), is not `UNRESOLVED_TYPE_REF` (it resolves), and
emits a crate `rustc` refuses — the third outcome FR-062 declares impossible.

The fourth is text. Identifiers are derived from `displayName`, a display name
standing in for a semantic identity; ECMA-262 pattern semantics are cited
without saying whether the engine runs in Unicode mode, which decides `\p`,
`.`, and lone surrogates; ISO 8601 bounds are compared lexicographically, which
is wrong for every offset and every duration; and arbitrary JSON is required to
survive a byte-identical round trip through a `BTreeMap` and an `f64`.

Eight findings are high. US-011 names the risk they share: an emitter that
degrades quietly is worse than no emitter, because it looks like evidence.

| FND-947 | high | `unknownPolicy` is required on all eight kinds and disposed for one. `semantic-ir.schema.json#/$defs/typeDefinition` lists `unknownPolicy` in `required` for every `kind`, so `{"kind": "scalar", "scalar": "boolean", "unknownPolicy": "preserve"}` is schema-legal and reader-legal — `reader.mjs` never reads `unknownPolicy` at all. | FND-948 | high | `Option<Nullable<T>>` collapses the two states it exists to separate. FR-054 composes the axes as collection, then nullability, then presence, so an `optional` `nullable` field is `Option<Nullable<T>>`, and it names no serde attribute for the presence axis. Under derived serde, `impl<'de, T> Deserialize<'de> for Option<T>` visits `null` and yields `None` without ever reaching `Nullable`, so an absent member and an explicit `null` both deserialize to `None`; on the way out, `None` serializes as `null` unless a `skip_serializing_if` nobody required is present, so an absent member round-trips to a present `null`. | FND-949 | high | The boxing rule quantifies over fields, so two cycle shapes emit a crate that does not compile. FR-054 introduces `Box` "at every field whose resolved target lies in the same component as its owner". Counter-example one, an alias cycle: types `A` (`kind: "alias"`, `target: B`) and `B` (`kind: "alias"`, `target: A`), referenced by no field. `reader.mjs`'s `checkDefinition` resolves `fields`, `constraints`, `relationships`, `operations`, and `clauses` and never resolves a definition's own `target`, `items`, or `values`, so no cross-field rule fires; FR-058's `UNRESOLVED_TYPE_REF` does not fire either, because each target resolves to a definition. FR-054 emits `pub struct A(pub B); pub struct B(pub A);` — `rustc` E0072, recursive type has infinite size. Counter-example two, a variant cycle: `{"kind": "union", "variants": [{"name": "V", "payloadType": "<self>"}]}` emits `pub enum U { V(U) }`, the same error, and a variant is not a field so no `Box` is introduced. Both violate FR-062's declared property that generation "either emits a compiling crate or emits zero files with a blocking diagnostic and never a third outcome", and FR-054-AC-7 tests only the three record-field shapes. Compounding it, the "type-reference graph" whose strongly connected components are computed is never defined: whether its edges include alias targets, `items`, `values`, `payloadType`, relationship targets, and operation parameter and return types decides the component set and therefore the boxed set, and two readings box differently while both satisfy "depend on the graph alone". | FR-054, FR-054-AC-7, FR-058, FR-062, EC-70, EC-54, ERR-121 |
| FND-950 | high | A display name stands in for the semantic identity. | FND-952 | high | The pattern machinery never says which ECMA-262 mode it decides, and Rust cannot be handed part of the language it must decide. `classifyPattern` "SHALL parse the pattern as an ECMA-262 pattern" with no flag set stated, and the difference is not cosmetic. Run against node: `new RegExp("^\\p{Lu}+$").test("p{Lu}")` is `true` and `.test("A")` is `false` — without the `u` flag `\p` is an IdentityEscape matching a literal `p`, so a `\p{...}` pattern is not "unsupported", it is *silently a different language*, and it falls squarely inside FR-057's declared supported subset of "literal characters, escape sequences". `src/compiler/ir/reader.mjs` already made this choice — `new RegExp(String(operands.regex))`, with an inline comment that compiling in Unicode mode "rejects patterns a plain ECMA-262 engine accepts" — and FR-057 does not repeat it. The subject side is worse. Without `u`, ECMA-262 matches UTF-16 code units: `/^.$/.test("\u{1F600}")` is `false` and `/^.$/u.test("\u{1F600}")` is `true`. A generated Rust matcher over `String` is a code-point matcher by construction, so it answers `true` where the published engine answers `false`, for every astral subject and every pattern using `.`, a negated class, or a counted quantifier. And the published locus pattern accepts a lone surrogate — `p.test("\uD800")` is `true` — which a Rust `String` cannot hold at all, so `SourceLocusPath::try_new` cannot be *given* the input on which it would have to agree. FR-057-AC-6's probe alphabet `{a, /, backslash, ., :, U+000A, U+0000}` contains no astral character and no surrogate, so the equivalence harness cannot find any of this. Neither can FR-057-AC-5, whose 40 declared patterns and seeded strings inherit the same alphabet decision, which no requirement states. `\d`, `\w`, `\s`, `\b`, and named groups sit in the same fog: `\b` is plainly outside the subset, but `\d` is an "escape sequence" and so is inside it by the words as written. | FR-057, FR-057-AC-3, FR-057-AC-5, FR-057-AC-6, FR-057-CON-2, GAP-002, EC-74, EC-75, TC-681, TC-682 |
| FND-953 | high | ISO 8601 bounds are lowered to lexicographic comparison, which decides the wrong order. FR-057 lowers `min`, `max`, `exclusiveMin`, `exclusiveMax` as "lexicographic comparison of the validated ISO 8601 form for `date`, `datetime`, `duration`", and `applicability.mjs` admits all four keywords on all three. For `datetime`, RFC 3339 admits an offset, and `"2020-01-01T00:00:00Z" < "2019-12-31T23:00:00-05:00"` is `false` while the second instant (`2020-01-01T04:00:00Z`) is genuinely later — so a `max` of `2020-01-01T00:00:00Z` *accepts* a value four hours past the bound. For `duration` no lexicographic order is even approximately right: `"P1D" < "PT2H"` is `true` while `P1D` is twelve times the longer, and `PT60M` and `PT1H` are one duration and two strings, so an `exclusiveMin` of `PT1H` admits `PT60M`. `date` alone is safe, and only because RFC 3339 full-date is fixed-width and offset-free. ## Failure Dispositions

| Failure | Required disposition |
|---|---|
| A member the schema requires on every kind, disposed for one kind | State a row for every kind, or refuse the pairs with no row under a registered code; never leave a required member with a rule that only one kind can execute |
| Absence and an explicit `null`, in any composition | Represented by two distinct Rust values and two distinct wire forms, with the serde attributes named in the requirement; a rule that names a type without naming `default`, `skip_serializing_if`, and the deserializer has not stated a mechanism |
| A cycle that closes through an alias target, a variant payload, a `items`, a `values`, or an operation return | Boxed, or refused with a blocking diagnostic; the graph whose components are computed must have its edge set written down, because the edge set decides the boxed set |
| A generated identifier | Derived from the semantic identity, or derived from a name whose uniqueness the contract enforces; never from a display name the contract lets two identities share |
| A name outside the deriver's alphabet | Refused under `UNRENDERABLE_NAME`, never silently truncated to the characters the deriver happens to recognise |
| An ECMA-262 pattern or subject | Decided under one declared mode, stated in the requirement, with the probe alphabet covering astral characters and the surrogate range; an equivalence harness that cannot express an input has not tested it |
| An ordered comparison over a date, datetime, or duration | Performed over a normalized instant or magnitude; lexicographic order is the answer only where the form is fixed-width and offset-free, and the requirement must say which forms those are |
| A value from the open JSON space required to round-trip | Round-tripped over retained bytes, or the round-trip claim narrowed to a declared canonical form; a `BTreeMap` and an `f64` are a lossy pair and the loss must be named, not asserted away |
| A kernel scalar with no stated wire encoding | Encoding stated in the requirement before any golden or corpus answer freezes it; the first emitted byte must not become the contract |
| A `defaultValue`, an `enumValues` operand, or an `occurrence.value` that disagrees with its declared type | Refused with a registered code at generation; never rendered into source and left for `rustc`, and never rendered by the host runtime's own number formatting |
| An emitted file that carries no semantic identity | Named in a manifest shape that admits it, or the requirement states which files the manifest omits; never given an invented identity to satisfy a `minItems` |
| A code the backend can emit | In exactly one closed registry, in one namespace, with the reader crate explicitly inside or outside it; a shared spelling in two namespaces is one code or it is a defect |
| An adapter that cannot finish | A non-zero exit and a named failure the harness reports as a failure; a truncated array, a duplicate answer, and a panic must never read as agreement or as absence |
