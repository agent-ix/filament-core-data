# Risk and complexity review

## Summary

Issue #21 is two projects wearing one ticket. The first is a JavaScript code
generator: 12 new files under `src/compiler/backends/rust-serde/` that map the
IR to Rust, derive identifiers, emit a crate, lower constraints, close a
diagnostic registry, and publish a branch register and a mutation catalogue.
The second is a Rust program of comparable weight to the artefact it is judged
against: five crates in a repository that today contains zero lines of Rust —
`crates/semantic-ir` (a fourth independent IR reader deciding the published
schema layer, the cross-field rules, a byte-exact normalization and a
compatibility classifier), `crates/conformance-adapter`, two consumer crates,
and the generated crate itself — plus a self-written ECMA-262 matcher, a
proved-validator registry with a differential harness, committed goldens, and a
platform support matrix. Between them, 116 acceptance criteria, 39 named
constraints and 100 test rows (TC-645..744), every one of them `🚧 planned`.

The long pole is `crates/semantic-ir` (FND-963). It is the only deliverable
whose size is set by an artefact outside this ticket: it must reproduce the
30 published diagnostic codes of `conformance/diagnostic-codes.json` (28
cross-field, 2 schema-layer) and match, byte for byte, a `normalized` string
produced by `JSON.stringify` inside a 1484-line JavaScript oracle it is
forbidden to read. Everything else in the ticket is bounded by the mapping
table. Nothing else is bounded by another language's number formatter.

The three risks that should change the plan before tasking are: the
independence constraint FR-059-CON-1, which is asserted by a static check that
cannot detect the thing it forbids (FND-964); the `normalized` byte comparison,
which the harness applies to *every* case while FR-059-AC-3 claims it only for
non-invalid ones, and which drags ECMAScript number formatting into a Rust
crate (FND-965, FND-966); and the suite, which today is 409 tests in 30.6s wall
and which this ticket would extend with up to 73 `cargo build` invocations, a
package-and-unpack cycle, a mutation harness at detection score 1.0, a
4096-document fuzz, and property runs of roughly 4 million matcher executions
(FND-967).

One finding is not a risk but a fact: this branch is already red. `pnpm run
test` reports 1 failed / 408 passed, at `test/compiler.test.ts:366` —
`declared but absent: src/compiler/backends/rust-serde/mapping.mjs`
(FND-968).

Safe to build first, in this order: FR-055 (`names.mjs`, pure, self-contained,
10 ACs), then FR-054's mapping model against the four corpus bases, then FR-056
and FR-060's goldens for those bases. `crates/semantic-ir` and FR-059 should be
tasked separately and started early in parallel, because its calendar length
is set by the reader, not by the generator. FR-057's 40-pattern property claim
and FR-062's mutation score should not be tasked until FND-969 and FND-975 are
decided.
