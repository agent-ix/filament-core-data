# NFR-041: Single-owner regeneration of shared generated artifacts

## Statement

The repository SHALL regenerate, from the rebased tree and by one named command,
every committed artifact that is a function of the whole tree rather than of one
change, and SHALL NOT reconcile such an artifact by a textual merge.

## Scope

- Applies to: the conformance coverage account, the generated compiler
  diagnostics document, the compiler inventory, and the computed execution
  summary of the test matrix — every artifact a generator writes from the merged
  set of branches rather than from any one of them.
- Applies to: any artifact added later whose content depends on more than the
  change that commits it.
- Out of scope: goldens and expected packages. Those are assertions about one
  input and are a function of that input alone, so they are regenerated by their
  own backends and are not shared in this sense.
- Out of scope: whether a given account should be committed at all. Deriving one
  at check time discharges this requirement for that artifact; it is a per
  artifact decision, not a policy stated here.

## Rationale

This requirement answers [filament-core-data#63](https://github.com/agent-ix/filament-core-data/issues/63).

Three backend tickets ran against one tree and four artifacts were a function of
the merged set of them. Each branch regenerated all four and committed the
result. Whichever merged second committed an account that reproduces nothing,
and the gate asserting that the committed bytes reproduce from a live run went
red on the trunk for work the branch did not do.

The failure is not a merge conflict, which is visible and is resolved by a
person. It is a clean textual merge producing a file no generator would ever
write — a result that is wrong in a way no reviewer sees, because the diff looks
like the union of two correct diffs.

No branch can fix this from inside itself. One branch's discipline of stating
deltas rather than absolutes protects that branch and does not stop a sibling
carrying an absolute, nor make the trunk's committed account reproduce. The rule
therefore belongs to the trunk and has to be findable from a rebase, which is
the moment it is needed and the moment nobody reads a ticket.

A gate that reports only a byte difference is half a gate here. The reader
already knows the bytes differ; what they do not know is which of four
generators to re-run. Naming the generator is the difference between a
thirty-second fix and an afternoon of bisecting.

## Measurement and Evaluation

| Metric | Target | Threshold | Method |
|--------|--------|-----------|--------|
| Shared generated artifacts reachable from one named command | all | all | Inspection |
| Committed shared artifacts that reproduce byte for byte on the trunk | all | all | Test |
| Failing reproduction reports that name their generator | all | all | Test |
| Acceptance criteria asserting a whole-corpus absolute a sibling merge falsifies | 0 | 0 | Inspection |
| Places a rebase will find the regeneration rule | at least 1 | at least 1 | Inspection |

## Verification

Run the named command on a clean rebased tree and observe every shared artifact
is unchanged. Falsify it by editing one byte of each shared artifact in turn and
observing the gate fails and names the generator that writes it, not merely the
path that differs.

Take two branches that each regenerate a shared artifact, merge both, and
observe the trunk's gate is green only after the named command has run — and
that the textual merge of the two, committed without regeneration, is reported
rather than accepted.

## Acceptance Criteria

| ID | Criteria | Verification |
|----|----------|--------------|
| NFR-041-AC-1 | One named command regenerates every shared generated artifact | Inspection |
| NFR-041-AC-2 | On a clean trunk every committed shared artifact reproduces byte for byte | Test |
| NFR-041-AC-3 | A reproduction failure names the generator to re-run, not only the differing path | Test |
| NFR-041-AC-4 | The regeneration rule is recorded where a rebase will find it | Inspection |
| NFR-041-AC-5 | No acceptance criterion in any bundle asserts a whole-corpus absolute that a sibling merge falsifies | Inspection |
| NFR-041-AC-6 | Two branches regenerating one artifact reconcile by regeneration, and a textual merge of the two is reported rather than accepted | Demonstration |
| NFR-041-AC-7 | An artifact derived at check time rather than committed satisfies this requirement without a reproduction gate | Inspection |
