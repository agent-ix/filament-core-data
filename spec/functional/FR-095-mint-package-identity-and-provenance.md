# [FR-095] Mint package identity, envelope digests, node identities, and provenance

## Description

The extraction frontend SHALL derive the IR document's `source` and `package`
envelope, every node identity, and the provenance sidecar from loaded bundle
bytes, loaded manifest bytes, and pinned crate metadata alone, so that every
value in the emitted document traces to a source byte or a manifest value and
none is inferred from the host.

## Rationale

`source.dialect` is `spec-bundle` because the Markdown bundle is the authored
source and the extraction record is not a projection of it; this is the
declared reading of issue #77, cited here, and it changes no byte of
`schema/**`. The identity grammar is FR-020's; the `spec-bundle` value is
FR-030's. The quire-rs pin is a git `rev` (at or after `a874fb6`, quire-rs#411)
because no release tag contains it; the pin moves to a tag under quire-agent-c's
sweep (quire-rs#417), and the provenance golden is regenerated by
`--write-goldens` as one deliberate commit per pin move (FR-098-CON-2).
Node identities are minted by the one rule of
`docs/semantic-data-system/contracts-v1.md` §Identity minting (issue #87,
CR-087-1), which FR-034 originates and FR-053 implements in
`src/compiler/frontend/typespec/identity.mjs`, so that the TypeSpec frontend
and this frontend mint one identity for one declaration; the slot list below
restates the contract's table and yields to it where they differ. The
`type` part is slugged like every other part, so a record named
`Config_Version` mints `type/Config-Version` on both sides; the shared table
of AC-16 lives inside the crate and its node side is a verb of the harness
FR-099-CON-1 already names, so FR-098-CON-1, FR-098-AC-10, FR-099-CON-1,
FR-099-AC-5, and NFR-032's permitted list need no widening and no file under
`test/` is added or edited for issue #87 (CR-087-2).

## Inputs

- The bundle's `spec.md` frontmatter `org`, `name`, and optional `version`, already refused by FR-091 (`BUNDLE_UNIDENTIFIED`) when absent or not matching `packageIdentity`
- Every loaded document's bundle-root-relative path and raw bytes, from FR-091
- Each loaded module's manifest bytes, `name`, `version`, and `semantic.contract_version`
- The root `Cargo.lock`, embedded at build time with `include_str!`, for the `quire-rs` version and git revision NFR-033 pins and the frontend crate's own version
- The `displayName` FR-093 fixes for each record, and the kernel scalar name FR-092 fixes for each scalar definition

## Outputs

- `crates/extraction-frontend/src/identity.rs`: `PackageIdentity`, `slug(name) -> Result<String, Unsluggable>`, the `type_identity`, `alias_identity`, `field_identity`, `constraint_identity`, `relationship_identity`, `operation_identity`, `variant_identity`, `clause_identity` minters (a parameter is minted by `field_identity` with the operation as a middle part; there is no `param_identity`), `diagnostic_code`, and the collision check that raises `DUPLICATE_IDENTITY` over every minted identity of one lift
- `crates/extraction-frontend/fixtures/identity-cases/identity-cases.json` (with its `PROVENANCE.json`, `authored`): the shared identity table of AC-16, authored from `contracts-v1.md` §Identity minting, with four row shapes — identity rows (`package`, `slot`, `parts`, `identity`), alias rows (`package`, `record`, `field`, `identity`, `displayName`), `diagnosticCode` rows (`package`, `parts`, `keyword`, `code`), and refusal rows (`package`, `slot`, `parts`, `refuses: "UNSLUGGABLE_NAME"`); its rows include `Config Version`, `Config_Version`, `created_at`, `minLength`, `core.data`, and `_`
- The `identity-cases --table <file>` verb of `scripts/extraction-frontend-harness.mjs`, which imports `src/compiler/frontend/typespec/identity.mjs` and prints, for every row of the table, what that implementation mints or refuses; the Rust test of AC-16 runs it over the same table and compares. No file under `test/` is added or edited, and FR-098-CON-1, FR-098-AC-10, FR-099-CON-1, FR-099-AC-5, and NFR-032 need no widening: the table is under `crates/extraction-frontend/**` and the harness is already one of FR-099-CON-1's six paths
- `crates/extraction-frontend/src/envelope.rs`: `source_block(bundle)`, `package_block(bundle, modules)`, `provenance_record(bundle, modules)`
- The provenance record, written by FR-097 as the `<out>.provenance.json` sidecar on every successful lift

## Behavior

### The `source` block

- The frontend SHALL set `source.identity` to `ix://<org>/<name>/spec`.
- The frontend SHALL set `source.dialect` to `spec-bundle`.
- The frontend SHALL set `source.version` to the `spec.md` frontmatter `version` where present and to `0.0.0` otherwise.
- The frontend SHALL set `source.digest` to `sha256:<hex>` over the byte sequence formed, for each loaded document in path order under code-point comparison, by the document's bundle-root-relative path bytes, one `0x00` byte, the document's raw bytes, one `0x00` byte.

### The `package` block

- The frontend SHALL set `package.identity` to `<org>/<name>`.
- The frontend SHALL set `package.version` to the same value as `source.version`.
- The frontend SHALL set `package.manifestDigest` to `sha256:<hex>` over the concatenation of the manifest bytes of every loaded module, in module-name order, not only of the module declaring the bundle's object types.
- The frontend SHALL set `package.mappingVersions` to the one-element list holding the module's `semantic.contract_version`.
- The frontend SHALL set `package.profileVersions` to `[]`.
- The frontend SHALL set `package.lockDigest` to `sha256:<hex>` over the lines `<module package>@<module version>:<manifest sha256>`, where `<module package>` is the module's `semantic.package` (for example `agent-ix/spec-objects-business@0.3.0:<sha256>`), one per loaded module, sorted by code point and each terminated by `\n`.
- The frontend SHALL emit `occurrences: []` and top-level `extensions: []`.

### Node identities

- The frontend SHALL mint every node identity by the rule of `docs/semantic-data-system/contracts-v1.md` §Identity minting, rooted at `ix://<org>/<name>/`.
- The frontend SHALL mint no identity by any other rule.
- The closed slot list, with `<Name>` the declaring artifact's id (FR-143) and every `<…>` part — `<Name>` included — passed through `slug`, is:
  - type: `ix://<org>/<name>/type/<slug(artifact id)>` (artifact `FR-005` → `type/FR-005`), or `type/<KernelScalar>` for a scalar definition (a kernel scalar name is alphanumeric, so its slug is itself; the same rule FR-046 applies)
  - constrained-field alias: `ix://<org>/<name>/type/<slug(Name)><Field>`, where `<Field>` is `slug(field)` with its first character upper-cased (`FR-001`, `revision` → `type/FR-001Revision`; `FR-001`, `created_at` → `type/FR-001Created-at`), the alias FR-093 mints per field carrying constraints; the alias node's `displayName` is the artifact's `displayName` followed by the field name verbatim with its first character upper-cased (`NoteRevision`, `NoteCreated_at`)
  - field: `ix://<org>/<name>/field/<Name>-<field>`
  - operation parameter: `ix://<org>/<name>/field/<Name>-<operation>-<param>`; a parameter is a `field` identity with the operation as its middle part, and there is no `param/` slot
  - constraint: `ix://<org>/<name>/constraint/<Name>-<field>-<keyword>`
  - relationship: `ix://<org>/<name>/relationship/<Name>-<verb>-<TargetName>`, with `<TargetName>` the target artifact's id
  - operation: `ix://<org>/<name>/operation/<Name>-<operation>`
  - enumeration variant: `ix://<org>/<name>/variant/<Name>-<value>`
  - clause: `ix://<org>/<name>/clause/<Name>-<clauseId>`
- The frontend SHALL compute `slug(value)` as the contract states it: every run of characters outside ASCII `[A-Za-z0-9]` replaced by one `-`, leading and trailing `-` trimmed, case preserved (`Config Version` → `Config-Version`, `created_at` → `created-at`, `versionNumber` → `versionNumber`); a non-ASCII letter is a separator (`semanticIdentity` admits only `[A-Za-z0-9._~:/-]`). Each part is slugged and the parts are joined by `-`.
- If a part slugs to the empty string, then the frontend SHALL raise `agent-ix.extraction-frontend.UNSLUGGABLE_NAME` at the declaration's locus, blocking, and SHALL NOT drop the part or mint the identity.
- The frontend SHALL derive each constraint's `diagnosticCode` as the contract states it: `agent-ix.<slug(name) lower-cased>.<UPPER_SNAKE(Name)>_<UPPER_SNAKE(field)>_<UPPER_SNAKE(keyword)>`, where `UPPER_SNAKE` is `slug` with `-` replaced by `_` and upper-cased and a camelCase name or keyword is not split (`Note`, `revision`, `min` under package `records-and-scalars` → `agent-ix.records-and-scalars.NOTE_REVISION_MIN`; `maxLength` → `MAXLENGTH`).
- The frontend SHALL treat a `diagnosticCode` as a datum and not as an identity: two constraints on distinct identities whose codes coincide across records (`Status.id` and `status.id` under `min`, both `STATUS_ID_MIN`) raise nothing; FR-093's per-record `DUPLICATE_CONSTRAINT` is the only code-level check.
- The frontend SHALL mint identities that match `common.schema.json#/$defs/semanticIdentity`.
- The frontend SHALL apply the contract's three collision cases in order: (a) FR-093's `DUPLICATE_TYPE_NAME` over equal verbatim `displayName` values and kernel-scalar names, before any identity is minted; then (b) `UNSLUGGABLE_NAME` at the later of two distinct names whose slugs coincide (`created_at` beside `created__at` on one record; two enumeration rows slugging alike, FR-093); then (c) `DUPLICATE_IDENTITY` over every other pair of minted identities, so that a node refused under (a) or (b) is never a party to (c).
- If two nodes of one lift mint the same identity under distinct names with distinct slugs (an artifact with id `FR-001Revision` beside artifact `FR-001` with a constrained field `revision`, whose alias is `type/FR-001Revision`; a field beside an operation parameter of the same owner minting one `field/` identity), then the frontend SHALL raise `agent-ix.extraction-frontend.DUPLICATE_IDENTITY` at the later node, blocking, naming both identities and carrying the earlier node's locus in `related`.
- If two nodes of one lift mint the same identity, then the frontend SHALL NOT emit either node under that identity.
- The frontend SHALL order nodes for every collision case with kernel scalar definitions before every authored declaration, and authored declarations by bundle-root-relative path, then start line, then start column.
- The frontend SHALL mint distinct identity sets for two artifacts with distinct ids, whatever their `displayName` values.

### Provenance

- The frontend SHALL produce a provenance record carrying: `source.identity`; for each loaded module its `name`, `version`, and manifest `sha256`, in module-name order; the `quire-rs` crate version and git revision that the embedded `Cargo.lock` pins; the vendored semantic-core version; and the frontend crate version from the same embedded `Cargo.lock`.
- The frontend SHALL obtain the `quire-rs` revision and its own version only from the embedded `Cargo.lock`, never from `env!`, `option_env!`, or a process environment read.
- The frontend SHALL omit the bundle root and module root paths from the provenance record; the record names a module by `name`, `version`, and manifest digest, which is how a test joins it to the vendored module's `PROVENANCE.json` revision.
- The frontend SHALL write no clock reading, hostname, username, absolute path, or environment value into the provenance record, per FR-019-CON-1.

## Constraints

| ID | Constraint | Type | Validation |
|---|---|---|---|
| FR-095-CON-1 | The frontend SHALL compute every value in the emitted `source` and `package` blocks and in the provenance record as a pure function of loaded document bytes, loaded manifest bytes, and the embedded `Cargo.lock`. | Determinism | Test |
| FR-095-CON-2 | The frontend SHALL NOT read the bundle's git history, tags, or remotes to mint a version, digest, or revision. | Determinism | Static analysis |
| FR-095-CON-3 | The frontend SHALL NOT widen `frontendDialect`; `spec-bundle` is the only value it stamps. | Compatibility | Test |
