# FR-137: Spell semantic identity alike in every generated package

## Description

Every generated package SHALL name its semantic-identity artifact *identity* and
SHALL NOT name any artifact *metadata*.

[ADR-0007](../../docs/semantic-data-system/adr/0007-emitted-set-contract.md)
declares the conceptual outputs and rules that the emitted set is realised
idiomatically per language rather than fixed by file name. This requirement
fixes the one thing it does not leave to the language. It is the only part of the emitted set stated as a spelling, because it
is the only part a consumer cannot reason around: every other difference between
the targets is explained by a language property, and a name is not.

Two targets already satisfy this and are changed by nothing here. The JSON
Schema emission carries semantic identity inline on each schema node as
`x-agent-ix-semantic-id`; the Python package delegates its types to a pinned generator. Both are
declared realisations under ADR-0007, not omissions, and both are named here so
that "every generated package" is a claim over a stated population rather than
over whichever targets happened to be inspected.

The repair moves names, not data. A generated package after this change carries
every datum it carried before, reachable by the same member names within each
artifact. Where a datum moves between artifacts it does so because the artifact
it sat in is being retired, and the requirement states where it lands rather
than leaving the move to an implementer.

This is a compatibility change under
[FR-051](./FR-051-classify-contract-compatibility.md) for a consumer that
imports a generated module by path, and is sequenced as one. It is not a
compatibility change in the contract the package describes.

## Inputs

- A semantic IR document accepted by a backend that emits a package of files
- The committed golden packages that assert each backend's emitted bytes
- The backend specifications that state where each of the five concepts lands

## Outputs

- `src/compiler/backends/rust-serde/crate.mjs`, emitting `src/identity.rs` and
  no `src/metadata.rs`
- `src/compiler/backends/typescript-v1/metadata.mjs`, rendering the identity
  module
- The re-cut golden packages under `test/fixtures/rust-serde/goldens/` and
  `test/fixtures/backends/typescript/expected/`

## Behavior

- The Rust backend SHALL emit its semantic identity, roles, relationships,
  operations, clauses, occurrences and extensions in `src/identity.rs`.
- The Rust backend SHALL NOT emit a module named `metadata`.
- The TypeScript backend SHALL emit the document-level and per-type contract
  data that `metadata.ts` carried in `identity.ts`, under the same export names.
- The TypeScript backend SHALL NOT emit a module named `metadata`.
- Each implemented backend's specification SHALL name where each concept of
  ADR-0007 lands in that target.
- No implemented target SHALL emit an artifact whose name denotes the concept
  another target's artifact of that name does not denote.

## Constraints

| ID | Constraint | Type | Validation |
|----|------------|------|------------|
| FR-137-CON-1 | Every datum a generated package carried before this change SHALL be present after it; the repair renames artifacts and moves declarations between them and removes nothing | Integrity | Test |
| FR-137-CON-2 | The TypeScript package's public export surface SHALL NOT contain `SEMANTIC_METADATA` | Compatibility | Test |
| FR-137-CON-3 | The generated bytes SHALL remain reproducible: regenerating a committed golden after this change SHALL produce the golden's bytes exactly | Determinism | Test |
| FR-137-CON-4 | The JSON Schema and Python realisations SHALL be declared rather than changed, because neither carries the defect | Scope | Inspection |
