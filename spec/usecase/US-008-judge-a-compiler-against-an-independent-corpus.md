# [US-008] Judge a compiler against an independent conformance corpus

## Story

**As a** reviewer who has to decide whether the semantic compiler and its
Rust, TypeScript, and Python backends may be called production-ready
**I want** a conformance corpus whose cases and expected results are derived
from the published contract rather than from any implementation's output, and
a differential harness that judges every implementation against that corpus
**So that** a wrong or silently divergent implementation fails a gate instead of
blessing its own behavior as the baseline.

## Context

Issue #4 produced a single feasibility slice and one prototype emitter under
`spikes/typespec-feasibility/`. That emitter is the only thing in this
repository that has ever produced an "IR", and it produces a document shape the
published `semantic-ir.schema.json` rejects. Issue #19 promotes and rewrites it;
issues #21, #22, and #23 add Rust, TypeScript, and Python backends. If the
evidence for those tickets is generated by running them and recording what came
out, every one of them can be wrong in the same direction and still be green.

The published contract is already executable: thirteen JSON Schemas under
`schema/semantic/v1/`, the cross-field rules written down in
[`contracts-v1.md`](../../docs/semantic-data-system/contracts-v1.md), and the
semantic-core declaration grammar of [US-007](./US-007-declare-archetypes-against-a-shared-grammar.md).
That is enough to author cases and expected results without running anything.

## Acceptance Examples (Illustrative)

### [US-008-EX-1] A case is authored from the contract, not from a run

- **Given** a corpus case that asserts a field whose `multiplicity.upper` is `0` raises `UNSUPPORTED_MULTIPLICITY`
- **When** the reviewer asks where the expected result came from
- **Then** the case cites the contract clause and schema pointer it was derived from, and records that no implementation run produced it

### [US-008-EX-2] A silently wrong implementation fails

- **Given** an implementation that reports a diagnostic for a construct the contract accepts, or accepts one the contract rejects
- **When** the differential harness runs the corpus against it
- **Then** the harness reports the case, the expected result, the observed result, and the exact source locus, and exits non-zero

### [US-008-EX-3] A missing backend is visible, not absent

- **Given** no Rust backend exists yet
- **When** the harness runs
- **Then** the Rust adapter reports `unavailable` with its owning ticket, the coverage accounting shows the unmet rows, and no case is silently skipped

### [US-008-EX-4] Two implementations that agree with each other but not with the contract still fail

- **Given** two implementations that both resolve an alias cycle to "unresolved type reference"
- **When** the oracle expects an alias-cycle diagnostic at the cycle's locus
- **Then** both implementations fail that case, because each is compared with the oracle and never with the other

### [US-008-EX-5] A discovered defect becomes a permanent case

- **Given** the prototype emitter derives nullability from a substring of a rendered type name
- **When** the defect is recorded
- **Then** the corpus gains a case whose type name contains the substring but whose type is not nullable, and that case stays in the corpus after the defect is fixed

## Options (Exploratory)

The expected results could be golden documents captured from a reference
implementation, hand-authored per case, or computed by an independent oracle.
The corpus could live in this repository, in a separate corpus repository, or
inside each backend. Backend participation could be opt-in (absent backends
skipped) or declared (absent backends recorded). The functional requirements
settle each of these.

## Constraints (Contextual)

The corpus publishes no package, enlarges no published surface, and changes no
consumer. It does not modify `spikes/`, `src/`, the semantic-core package, the
frozen v1 fixtures, the published schemas, or any repository owned by another
project. It targets the published contract as merged; where it disagrees with
the contract or with a merged artifact, it records the disagreement with an
owning issue rather than repairing either side.

## Dependencies (Contextual)

Depends on the semantic IR contract ([US-006](./US-006-declare-typed-domain-structure.md),
FR-027..FR-030) and the semantic-core declaration grammar
([US-007](./US-007-declare-archetypes-against-a-shared-grammar.md), FR-031..FR-034).
Judges issue #19 (compiler core) and issues #21, #22, and #23 (Rust,
TypeScript, and Python backends). Runs in parallel with issue #27 and issue #19
so that the yardstick is not authored by the implementer.

## Priority and Risk (Informative)

Priority is P0. The principal risk is a corpus that only restates what an
implementation already does — an oracle written by the implementer of the thing
it checks is not an oracle. The second risk is a corpus so large that it is
maintained by regenerating expectations, which is the same failure wearing a
bigger coat.
