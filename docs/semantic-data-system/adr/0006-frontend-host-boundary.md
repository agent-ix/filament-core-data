# ADR-0006: Inject the extraction producer, as the formatter is injected

## Context

The `spec-bundle` frontend is registered and not implemented.
`src/compiler/frontend/spec-bundle/frontend.mjs` is twenty-seven lines that
return `FRONTEND_NOT_IMPLEMENTED`. It is a placeholder rather than a shim: it
spawns nothing and does not know that the implementation exists.

The implementation does exist. `crates/extraction-frontend` loads a repository
`spec/` tree through the Quire extraction contract and writes four artifacts —
the semantic IR document, its fingerprint, a diagnostics sidecar and a
provenance record — atomically, by temp-and-rename. Everything between load and
write is in memory. What is missing is the wire between the JavaScript seam and
that binary.

The obvious wire is a subprocess spawn followed by reading the sidecar the
binary wrote. That runs directly into a rule this repository states twice and
enforces:

> It lives outside `frontend/` because no module under that directory may touch
> `node:fs`: the frontends reach the file system only through the injected host,
> and a convenience read here would be the one exception that makes the rule
> unenforceable.
>
> — `src/compiler/dialects.mjs`

The rule is not decorative. `src/compiler/host.mjs` exists because the safety
and determinism properties the compiler claims are otherwise unobservable: "the
compiler reads nothing outside its roots" cannot be established by reading
source, because the pinned TypeSpec compiler does its own resolution and its own
dynamic import. It can be established by giving that compiler a host this
repository owns, so that a refusal is a refusal in fact rather than an assertion
about intent.

No ticket mentions this conflict. [#86](https://github.com/agent-ix/filament-core-data/issues/86)
describes roughly fifty lines of plumbing and says nothing about the boundary
those fifty lines cross. Left undecided, it gets decided by whoever writes the
plumbing, at the moment they discover the rule, under time pressure — and the
cheapest local move at that moment is an exemption.

The host today offers reads, an existence check, a directory walk, atomic
writes, and a module-load gate. It offers no way to run a program.

## The conflict the first draft missed

This decision was written, implemented, and falsified by its own implementation.
The falsification is recorded rather than quietly amended, because it is what
located the answer.

Adding a process capability to `src/compiler/host.mjs` fails **NFR-020-AC-5**,
which is not a changed-path gate or an annexation artifact but a normative safety
property with a test behind it:

> No module in scope imports a network-capable or code-executing built-in, and a
> fixture compile with `globalThis.fetch` stubbed never calls it.

The scope is every module under `frontend/`, `packages/`, `ir/` and `compat/`,
plus `pipeline.mjs`, `cli.mjs`, `json-locus.mjs` and `host.mjs`. The forbidden
set is `node:net`, `node:http`, `node:https`, `node:dgram`, `node:child_process`,
`node:worker_threads` and `node:vm`. `host.mjs` is named explicitly, and so is
`cli.mjs`.

Six suites went red, and every one of them was right.

## The answer was already in the repository

This is not a new problem here, and it already has a normative solution one layer
down. `src/compiler/backends/format.mjs` says so in its own header:

> This module is the one module under `src/compiler/backends/` that starts a
> child process, in the way `src/compiler/identity.mjs` is the one module under
> `src/compiler/` outside `cli.mjs` that reads a file. Every module under
> `backends/typescript-v1/` stays pure and receives the formatter as an argument
> rather than reaching for it.

The generation half needed to run an external program — the pinned formatter —
against generated bytes, with the same purity constraint on every module that
would use it. [FR-071](../../../spec/functional/FR-071-provide-the-generate-command-and-surface-fixtures.md)
answered it by putting the effect in exactly one module outside the pure set and
passing the *capability itself* in as an argument. The backends call
`options.format(text, path)`; they neither import the formatter nor know it
spawns anything.

The extraction half is the same shape with the effect on the other side of the
compile, and it takes the same answer.

## Decision

**The extraction producer is injected, exactly as the formatter is injected.**

- One module outside the NFR-020-AC-5 scope holds the effect, in the role
  `backends/format.mjs` already holds for generation. It is the only module in
  the extraction path that starts a child process.
- The `spec-bundle` frontend receives the producer as an argument on its
  request — `request.lift(...)` — and calls it. It imports nothing effectful,
  names no path, and does not know a process is involved, in the same way a
  backend does not know `format` spawns a binary.
- The frontend reads the producer's artifacts through the injected host, within
  roots the caller declared, as every frontend already reads.
- The frontend maps the exit code and the diagnostics sidecar into a
  `FrontendResult`. The seam's contract is unchanged: a blocking diagnostic and
  a non-null document still never come back together.
- A producer that is absent or exits non-zero is a *failure*, never a silent
  pass-through — the rule `format.mjs` states for its own binary, for the same
  reason: a silent pass-through produces an artifact nobody chose.

**NFR-020-AC-5 is unchanged.** No module in its scope gains an import. The
criterion is neither narrowed nor argued around, and the "the compiler executes
nothing" claim it supports stays exactly as strong as it was.

## Rationale

**The rule's purpose is observability and confinement, not abstinence** — but the
mechanism that delivers it here is injection, not a new host capability. The
first draft reached for the host because the host is where confinement lives for
*reads*. For effects the compiler must not contain at all, this repository's
answer is to put the effect outside the pure set and hand it in, and that answer
is already normative.

**Injection also keeps the seam's selection property**, which is what ruled out
lifting in the caller and passing the IR in as data. That alternative preserves
the safety criterion too, but it relocates frontend selection into the call
site: a caller that must lift before it can select has already selected, and
FR-045's seam exists so that a frontend is chosen by the `source.dialect` the
contract declares "rather than by whichever call site reached for it". Under
injection the caller supplies a *capability* and the seam still chooses when and
whether to use it.

**Narrowing NFR-020-AC-5 was considered and is not needed.** The argument for it
was real — NFR-020's threat model is input-controlled execution, and a
caller-declared program is not package-controlled — but it traded a strong,
cheaply-verified claim for a weaker one to buy something injection provides for
free. A criterion should not be weakened to accommodate a design when an
existing pattern satisfies both.

**Reimplementing the lift in JavaScript** duplicates 6,511 lines and creates a
second producer of one artifact, which is the divergence the conformance corpus
exists to detect rather than to cause.

**This does not settle where the binary comes from.** Whether the caller injects
a producer backed by a built binary, a `cargo run`, or a published artifact is a
separate question about build and distribution, and the injection point is where
that choice is made rather than hidden.

## Consequences

- One new module holds the effect and is named in its own header as the only one
  that does, matching `backends/format.mjs`. `host.mjs` gains nothing.
- `spec-bundle/frontend.mjs` becomes a shim over an injected capability and flips
  `implemented` to `true` in the frontend registry. Its current diagnostic names
  issue #36, which is closed; the accurate owner is #86.
- The frontend seam's request shape gains the producer, as the generation seam's
  options already carry `format`. A caller that supplies none cannot select the
  dialect, which is the honest failure: the capability is the dependency.
- An external producer can fail in ways no input can cause — a non-zero exit with
  no diagnostic, or a zero exit with no readable document. Neither is a defect in
  the bundle, so neither may be reported as one, and a new registry code names
  them. A reader who saw a bundle-shaped code would go looking in the bundle.
- A gate asserts that no module under `src/compiler/frontend/` imports an
  ambient-effect module. Today the rule is stated in two file headers and checked
  for `node:fs` by no test at all; NFR-020-AC-5 checks the code-executing and
  network built-ins but not `node:fs`.

## Status

Normative. It governs the #86 wiring and any later frontend that reaches an
out-of-process producer. It changes no generated byte, no published schema, and
no acceptance criterion.

The first draft of this decision was implemented and failed six suites, and the
correction came from reading what the repository had already decided for the
identical problem. That is the value #100 expected from writing this ADR before
the plumbing: the cost of being wrong here was a reverted branch, not a deleted
safety gate.
