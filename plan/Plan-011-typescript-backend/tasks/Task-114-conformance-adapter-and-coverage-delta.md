# Task-114: The conformance adapter, the first-run divergence count, and the coverage delta

## Scope

Wire the `typescript-backend` slot and let the independent oracle judge the backend. This is the ticket's headline evidence and the only acceptance evidence that was not produced by the thing it judges.

## Subtasks

- [x] Author `conformance/adapters/typescript-backend/adapter.mjs`. The harness spawns it with `cwd` at `conformance/` and passes nothing on stdin; it loads the corpus itself through the declared import API of `conformance/oracle/index.mjs` — `loadCorpus`, `listCases`, `buildInput`, `buildBefore` — and nothing else.
- [x] Emit one schema-valid `adapter-result` document per corpus case to stdout as a single JSON array, and exit `0`.
- [x] Compute `resultState` and `diagnostics` from `admitIr`, `normalized` from `normalizeIrForTarget`, and `classification` from `classifySurface` for `kind: "compatibility"` cases.
- [x] Never call `oracleVerdict` or `compare`, and never import `conformance/oracle/oracle.mjs`. Assert the prohibition statically over the transitive import set — computing the answer from the oracle is the one thing that makes the exercise worthless.
- [x] Read `caseDigest` from the corpus manifest rather than recomputing it from bytes the adapter chose.
- [x] Answer `supported` for every case. An `unavailable` answer from an available slot is a hard failure, and an `unsupported` answer would require the case to declare this adapter, which this work does not add.
- [x] Rewrite the `typescript-backend` row of `conformance/adapters/registry.json` with `status: "available"`, a `command`, and a rationale naming what now exists.
- [x] Record and commit the **first-run divergence count**: the number of cases that disagreed on the first complete adapter run, before any fix.
- [x] Regenerate `conformance/coverage.json` with `make conformance` and commit the regenerated bytes. State the result as this slot's own delta — the `typescript-backend` row's `unmet` falls from 111 to 0 and the corpus total falls by 111 — read from the regenerated account and never as a whole-corpus absolute.
- [x] Discharge the TypeScript half of the FR-042-CON-3 limitation in `src/compiler/inventory.json`, leaving the Rust half byte-identical for issue #21.
- [x] Record the measured figures, including the first-run divergence count and the count of ledger entries derived from the corpus register, in `spec/tests.md`.

## Deliverables

- `conformance/adapters/typescript-backend/adapter.mjs`
- The rewritten `typescript-backend` row of `conformance/adapters/registry.json`
- The regenerated `conformance/coverage.json`
- The discharged TypeScript half of `src/compiler/inventory.json`
- The measured figures in `spec/tests.md`

## Notes

- `conformance/divergences.json` is a **prohibited** path. A registered divergence converts a failing case into a matched one, so a permission to register divergences is a permission to pass. A disagreement this work cannot close is reported in the pull request and left failing for the owner.
- `conformance/thresholds.json` stays `proposed` and byte-unchanged; accepting a threshold is the issue #11 publication gate's act, not this ticket's. The rows are asymmetric — `rust-backend` permits one divergence, this slot permits zero.
- `mutationDetectionScore` is not adopted as a gate. `mutationScore()` in `conformance/runner/differential.mjs` computes detection from `oracleVerdict(...)`, so it scores the oracle and there is no per-adapter form to run.
- `coverage.json` is machine-generated and issues #21 and #23 regenerate it too. On rebase it is regenerated from the rebased tree, never merged textually; issue #63 owns the reconciliation.
- Nothing under `conformance/cases/`, `bases/`, `oracle/`, `runner/`, `schema/`, or any register but the registry row and the coverage account changes a byte.
